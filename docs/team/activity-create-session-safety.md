# 原朋友创建流程的来源身份与原键恢复

## 实际复现

离线实际 Editor、`useStoredWrite` 与 API client 探针确认两项失败：A 预览后切为 B，A 的安排/昵称会带 B bearer 发出创建 POST；A 的待确认原请求也可被 B 重试。证据中的昵称、地点、token 均为测试替身，不是真实用户信息。

## 最小修复

- 读取 `/me` 时同时保留当次 session，不能从组件当前 token 推断旧草稿属于谁。读取跨会话晚失败不清除新 session。
- 创建客户端重新核对显示来源 actor；最终 transport 前同步核对来源 session 和页面代次，Authorization 固定原值。隐藏、卸载或状态变化期间尚未发出的 POST 被阻断；已发出的请求不能保证撤销。
- 结果仍经原 ActivityDetail schema 校验，并核对 viewer actor。活动 ID 由服务器生成，不能与不存在的客户端预分配 ID 比较。现有公开 DTO 没有不可变 creator ID，不捏造该字段；合法重放返回更新后的版本/管理角色不会被当作错目标。
- 未确认结果不写已完成缓存、不删除原请求键；同一 actor 重新验证后可手动用新 session 重试原 body/key。B 不继承 A 的待确认创建、昵称、安排、地点或已完成页。不同账号的原本机记录不会因此被删除。
- 同一 actor 普通身份刷新保留未保存输入。登录失效/读取失败与未配置仍按既有错误边界提示，不把本机草稿当作服务器活动。
- 原 `weego-create-*` 草稿、待确认、完成存储键不变。未修改原创建请求/后端权限、审批、费用、本人不参加、时间校验或 AI 草稿生成规则。
- 原 ActivityEditor、AI 生成/填表与地点模块未改；回归额外将离线合法 AI 草稿经真实 mapper 填入原预览/创建链路，不调用真实模型或地图，也不称模型能力已实测。

## 验证 / 回退

实际组件测试覆盖原两项失败、跨账号隐藏、同账号刷新、新 session 的同 actor 原键重放、重复点击、/me 等待期间 hide/unload/unmount、已发晚结果、错 actor 成功响应、正常创建及 AI 派生表单。客户端回归额外覆盖最终 transport 检查、旧401隔离、规范化 actor、新服务器活动 ID 及合法较新重放。

这里只是离线 transport/native 替身、类型与构建层；不是真实数据库、微信登录/真机、模型或部署验收。源码回退使用 v12 快照；源码回退不等于数据库回滚，也不能撤销已发送的创建请求。统一剩余覆盖见 [写入口安全矩阵](write-boundary-matrix.md)。
