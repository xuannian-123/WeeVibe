# 发布、提前截止与人工定案：确认流程安全修复

修复前，发布需求和管理者提前截止在等待微信确认框时尚未上锁，双击可发起两个确认框。两项真实 React 组件探针均复现失败（应1次，实2次）；同一管理者 command 也承载人工定案，已一并覆盖。

修复范围仅这三个既有操作，不新增决策或服务端权限：

- 在打开确认框前同步锁定操作，等待期间禁用编辑/重复提交。
- 取消、确认框失败、网络失败均释放锁；未确认或失败不显示保存成功。
- 确认前后复验打开编辑器时的会话；新问卷版本、动作权限变化或页面卸载使旧确认失效。
- 网络请求已发送后不能保证撤销服务端提交；晚到响应不覆盖已刷新的页面，要求核对真实状态。
- 手工地点选择与说明在取消/失败时保留；最终选择仍只是建议记录，不替成员接受费用/安排、不发放席位。

25 项新增 React/jsdom/Taro 替身回归覆盖重复确认、取消重试、原生弹窗失败、会话/快照/权限变化、卸载、晚到响应及输入保留。最终全量测试、类型检查和构建以本轮交付日志为准，不等同于微信真机验证。

本轮没有改数据库、后台事务、群成员门禁、支付或 AI provider。需求时间/预算仍是自由文本，无法可靠自动认定硬冲突；“各填需求→全员候选方案→人工确认”中的全员 AI 协调和正式安排应用仍未接通。本次没有把规则统计称为 AI，也没有实现未确认的多数优先/成员舍弃策略。
