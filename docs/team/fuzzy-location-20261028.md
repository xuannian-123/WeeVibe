# 城市与附近地点改用大致位置

2026-10-28，关联 Issue35。微信于09:34将原 `wx.getLocation` 申请判为不通过，理由为所述业务场景不符合该精确位置接口的开放范围。此前09:26后台仍为审核中，后续交接以本次新结果为准。

城市识别和附近地点搜索只需要大致位置，因此客户端调整为 `wx.getFuzzyLocation`，同时另行申请该接口。新申请仍须微信审核；代码完成不代表接口资格或手机定位已通过。

## 实现

- 仅在用户主动点击定位或附近搜索后获取模糊位置；先验证本人会话和隐私授权，再申请 `scope.userFuzzyLocation`。原精确位置授权不作为模糊位置授权。
- `app.json` 改为模糊位置声明，删除精确接口声明；发布门禁同时拒绝残留的精确接口/权限声明。不回退到已被拒的 `wx.getLocation`。
- 官方原生模糊位置接口采用回调。适配器同时处理原生回调和Taro返回的Promise，统一请求GCJ-02坐标；坐标通过既有校验后才发送到当前会话的城市或附近查询接口。
- 保留系统定位关闭、微信系统权限拒绝、首次申请、拒绝后主动打开设置、取消、未配置和来源失效处理。打开设置只读模糊位置授权结果，不获取坐标或自动重放旧请求。
- 页面说明获取的是大致位置、搜索距离为估算；识别的城市仍需本人主动确认，手选城市和关键词搜索继续可用。真实地点本身的地图坐标及已有活动安排不受影响。
- Taro4.3.1的AuthSetting类型遗漏了此原生scope，使用局部类型补充；不扩大为任意权限或绕过运行时授权。

官方说明：[腾讯位置服务的getFuzzyLocation参考](https://github.com/TencentLBS/tencentmap-miniprogram-skill/blob/main/references/wx_location_api/wx.getFuzzyLocation.md)。该接口仍需场景准入申请；不能通过更换名字直接取得资格。

微信开发工具只检查实际页面、声明和当前能力状态，截图用于本次模糊接口申请。不伪造坐标、授权或申请通过结果；实体手机定位、城市识别和附近查询仍需在平台开通后核验。
