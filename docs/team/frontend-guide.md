# 共享界面与交互规范

2026-10-25。供各功能任务共同使用；这是当前可调整的设计基线，团队可以讨论整体修改，随后统一更新公共层。

## 统一入口

- 公共组件：[components/ui.tsx](../../apps/miniprogram/src/components/ui.tsx)。按钮使用Action，输入使用Field，信息分组使用Panel，提示使用Notice。
- 公共样式：[app.css](../../apps/miniprogram/src/app.css)。颜色、字号、间距、圆角及通用状态在这里共同维护。
- 请求与身份：[platform/api.ts](../../apps/miniprogram/src/platform/api.ts)，通过共享api-client调用，不在功能内另外建立身份或接口客户端。
- 生命周期与同步：[page-state.ts](../../apps/miniprogram/src/platform/page-state.ts)；不确定提交与恢复：[write-state.ts](../../apps/miniprogram/src/platform/write-state.ts)。

## 当前视觉基线

| 内容 | 当前参考 |
|---|---|
| 页面背景 | 暖白 #f5f7f3 |
| 主要文字 | #21372e |
| 主操作 | 绿底白字 #27674f，Action variant=primary |
| 次操作 | Action variant=secondary |
| 次级导航/辅助动作 | Action variant=text |
| 破坏性操作 | Action variant=danger，实施真实操作时明确确认 |
| 信息/错误/成功提示 | Notice tone=info/error/success |
| 表单与卡片 | 优先复用Field和Panel，沿用app.css字号/间距/圆角 |

源码沿用Taro现有designWidth=750及pxtransform，不直接假定浏览器CSS/DOM能力。功能样式采用自身前缀，新增局部样式不重定义全局.action、.panel、.heading等公共类。提取新的通用日期、地点或状态组件时，先确认复用接口再进入公共层。

每个主要操作区域应有清楚的主动作；其它操作降低视觉权重。主流程显示普通用户需要的内容，调试编号、版本/请求实现细节放说明或诊断区域。

## 一致的交互语义

- 申请中尚不占位，获批后才显示已加入；占位、接受状态与成局/预订分别表达。
- 未知费用显示待确认，不改为免费；地点资料不作为库存或预订事实。
- 登录只恢复本人身份，当前活动权限由服务端判定，不用昵称、入口或页面切换授管理权。
- 请求中防重复操作；失败保留输入；结果不确定保留原请求，不自动创建新请求重发。
- 首页/创建进入或手动操作时读取；详情仅前台20秒静默同步。后台读取不清输入、不反复切loading或禁用按钮；错误标过时、暂停写入，隐藏停同步。
- 关键默认值在提交前可见，完整预览后确认；本人参加意愿不自动勾选。

规范用于新功能和逐步完善既有页面，不能代替每个页面的实际体验检查。

## 功能PR的界面复核

提交时说明用户问题、最终行为、模块/共享文件、相关截图和实际操作结果。另一位成员查看整页与前后流程：入口是否明确、术语是否一致、空/错/加载是否可理解、默认值是否说清、修改是否影响其它模块。对无视觉变化的目录提取，核对重构前后同一流程和布局即可。

公共样式、组件接口或导航变化先由本轮可轮换的集成维护人协调受影响任务，再小步合并；不固定某个人永久负责前端，也不限制功能负责人提出产品改进。
