# 游客灵感：登录后返回与关键词保留

依据已确认导航需求“登录成功后返回原目标，不丢草稿”。这次只修复游客从灵感发起登录时丢失目标及当前输入的问题，不新增地点供应商、权限、后端或通用跨页面草稿系统。

## 当前行为

1. 游客在灵感输入关键词，主动点击搜索、附近或我的收藏时，先进入登录。仅在本次 Home 内存保存目标为灵感、当前关键词（最多80字）和所选城市。
2. 明确点击微信登录后，原登录函数返回的身份须与原 `/me` 核验的身份及当前会话一致，才恢复灵感页和输入。合法 UUID 大小写按原契约统一。
3. **不自动执行此前点击的动作**：登录不会搜索地点、请求原生定位、打开地图、收藏地点或重放旧写入。用户须重新主动点击；已返回地点列表、选中地点、坐标和其他账号的私有收藏不装入返回目标。
4. 原生登录失败可明确重试，或“取消并返回灵感”，仍为同一游客时保留输入。若身份核验暂时失败，只保同一来源的待确认目标，不把它当登录成功；身份已变不将旧输入转给新账号。`/me` 已核验但账户数据503不阻碍回到公共输入，也不捏造账户或地点数据。
5. 明确选择另一个 Tab、打开其他页面/创建选择层/城市选择，最新操作取代旧登录返回；朋友聚会和大型团建仍使用原登录后进入原创建入口的行为，不自动发布活动。取消新目标不会复活更旧目标。
6. 隐藏、卸载、退出登录令旧返回意图失效；旧 Promise 不能导航、恢复旧关键词或释放新登录操作锁。旧请求已经发出时不能保证取消或撤销服务端已签发的会话；Home 传入可选的同步提交守卫，code/cloud 两种原登录路径在写本机会话前复核原操作、页面代次和原会话。旧成功迟回不覆盖新账号。其他不传守卫的调用保持原行为，不能把本片视为所有登录入口都已修复。

“取消并返回灵感”发生在尚未核验完的新会话中时，仅打开灵感空输入，不转交未核验来源的文本。任何恢复都不会自动触发原生或地点请求。

## 数据与范围

- 返回意图和恢复输入只在当前组件内存，不新增 storage、日志、数据库字段、接口或配置。不是跨重启/跨设备草稿持久化，也不声称全部 Tab 的任意输入都会保留。
- 游客当次输入与身份已明确的私有状态分开；外部账号改变、注销后再登录不会继承旧关键词、结果或坐标。
- 同一 React 批次输入后点击，使用最新关键词而非旧事件闭包。身份、页面代次和操作 ticket 分别约束来源、迟回和锁归属。
- 首页的账户加载保持成功/失败/空数据区分。真实 `/me` 核验成功不等于账户数据库、地图供应商或微信设备验收通过。

## 本地验证与回退

实际 React Home 与真实 Inspiration、原账户/地点客户端组合，替换原生微信、身份建立及 HTTP transport 为离线 fixture。覆盖缺口的2个原失败及控制组、登录成功/失败/取消、同批次输入、来源变化、迟回/新锁、创建优先级、无自动定位/搜索/写入；另以真实原登录 helper + Taro 替身核 code/cloud 提交守卫、旧成功/401不覆盖新token和原无参数调用兼容；独立探针和最终数量见交付日志。没有调用真实位置、地图、数据库或线上后端。

获准设备与匹配后端后：游客输入→登录→回灵感且输入仍在→确认无自动定位提示/地点请求→本人再点击搜索；另验失败取消、切账号和退出。见 [晨间验收](morning-acceptance.md)。源码与 dist 回退不会撤销已完成登录或服务端已有写入；本片没有数据库迁移。
