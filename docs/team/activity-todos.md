# WG-09：首页跨活动轻量待办

本片只汇总 Issue #9 / [第11号规则](../11-首版成局加入与补位规则.md) 明确的四类真实状态：**待审批、缺人、成员待接受、待交接**。它不是消息历史、未读通知或新的业务状态表，不增加短信、订阅推送，也不代替成员接受或接任。最终实现与验证数量以本轮冻结日志为准。

## 谁能看到什么

| 类型 | 来源与当前身份 | 不应误解为 |
|---|---|---|
| 待处理申请 | 非整场取消活动的当前管理者，来源为真实 pending 申请 | 不等于仍能批准；截止、开始或版本改变后原服务仍可能允许拒绝清理，进入详情再核对 |
| 开始前缺人 | 当前管理者，未取消且未开始的有效环节，已占席位少于最低人数 | 占位包含保位待重新接受者；已过报名截止仍可能缺人，但不承诺还能申请/批准，不自动招募 |
| 待查看安排变更 | 本人仍 joined、有效未来环节的已接受版本与当前版本不同；管理者只看成员待审阅的聚合 | 不替别人接受；缺少可信变更历史时仍由详情禁止接受，列表不造历史或保证可重新接受 |
| 待交接回应 | 有效 pending 交接的当前管理者与指定接任人；源管理者和管理版本仍匹配、活动未取消 | 接任人退出/资格不足不自动过期；原规则可能仍允许拒绝/撤回，能否接受以详情为准 |

缺人和安排审阅只提供开始前的首片范围，不声称用户规则永久禁止显示后期状态。**不额外添加待核实、待成局、费用/预订提醒或需求截止类型**。相关业务仍可在活动详情使用，与本片待办范围分开。

整场取消、已处理/已失效状态在新读取中不再产生对应事项；旧后端仅写取消标记也不能继续显示有效交接。管理权切换后按新的数据库当前管理者重新计算，原创建者无隐含管理待办。没有自动删除、过期或补写源记录。

## 只读接口与隐私

- 独立 `GET /api/v1/todos`，只用服务端验证的 session actor；客户端不能传 userId 冒认他人。
- 与 `/account` 独立。新接口未部署、版本不匹配、缺少第10条交接表时，应准确显示不可用/缺配置；不能替换为零待办，也不让原活动列表、资料、收藏一起失败。
- 聚合只选择必要状态/版本/人数/时点。管理者聚合与普通本人记录分开授权，不查询或传出私人资料、出发地点、路线、需求答卷、邀请令牌或成员姓名列表。
- 返回轻量活动与四类计数，单位明确区分环节、申请和待回应事项，不把跨段重复人次标成独立人数。点击进入同应用真实活动详情，重新读取权限/版本；不直接在待办卡上调用写接口，也不标记消息已读。
- 无新表、迁移、模型/地图调用、配置变更或外部通知。第9/10条真实迁移应用与真实数据库业务仍需另行授权和验证。

## 分页不是全局统计

每页最多 **50 个授权候选活动**，不是50条待办。一个活动可能有多类事项，也可能在这次真实计算中没有事项。按稳定活动创建时间与ID游标读取；`has_more` 只表示还有候选页。

- 当前页零事项但仍有更多候选时，界面必须提示继续查看，不能说“全局没有待办”。
- 多页数据不是永久有效。翻页重新核对身份、来源索引版本与相关时间边界；源已变则明确要求刷新，从第一页重新取得，不拼出假全量统计。
- 为使来源核对有界，候选索引元数据上限为 **2000 个活动**（相关待接交接元数据同样有2000条读取上限）；超过时明确能力不足/503，不截取并声称完整。正文仍按50候选分页，不加载或哈希全部私密正文。
- cursor 严格校验格式与大小，只用于定位和一致性检查，**不是授权令牌**；知道或修改cursor不能越过服务端当前身份过滤。
- 刷新清空旧页与游标，账号切换隐藏原账号数据；A的晚响应或401不能更新B的待办或清除B会话。失败与真实零项分开。

## 待执行的匹配后端验收

以下是后续获准环境中的手工步骤，不是真实微信/PG通过记录：

1. A管理多个活动，分别安排pending申请、缺少席位、成员待审阅和pending交接；GO显示来源真实四类，不出现自行新增核实/费用待办。
2. B仅参加活动时只看本人的安排审阅与发给本人的交接，不读其他人的申请/资料；A交权后旧管理事项消失，B取得相应管理事项。
3. 批准/拒绝、退出、重新接受、交接处理和整场取消后刷新，事项随原事实更新；保位未接受者不能被重复算成缺失席位。截止与开始边界按上表区分。
4. 分页边界50/51、同创建时间的不同ID、当前候选页零事项但有更多、翻页期间转权/解决/时间变化分别验证；源变化提示重读而非保留旧权假统计。
5. 取消段不产生缺人/审阅；目标已关闭的申请可清理不等可批准。交接资格变化仍待回应时不伪造自动过期；取消marker使交接失效。
6. 旧接口404/HTML、503缺配置、畸形200、身份切换、重复点击加载、隐藏/返回和晚响应不显示假成功或假空，也不向其他账号请求。
7. 所有卡片只跳真实详情，无POST、不自动替人处理、不发送通知；原账户与消息列表保持原行为。

离线 service/route/client/React fixture 与类型/构建不证明真实数据库分页、锁并发或微信生命周期。此前46项loopback HTTP没有覆盖本轮新增 `/todos`，不可沿用旧日志冒充。本轮另外提供扩至50项的干净环境loopback健康脚本，覆盖再约与待办的未认证拒绝/缺配置/envelope；结果仅在本轮最终日志与构建指纹吻合且自建服务已停止时成立，仍不是已认证业务或真实DB验收。
