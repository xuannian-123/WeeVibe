# 退出 / 晚到确认与页面生命周期

## 已复现与修复

1. 修复前的实际组件探针有三项失败：重复点击退出、重复点击晚到会打开两个确认框；组件卸载后确认返回仍发起操作。
2. 首轮修复后的独立审计另发现两项失败：确认已通过，但身份读取 `/me` 尚未返回时隐藏或卸载页面，随后仍会发起新的 POST。此次把生命周期检查传入参加状态客户端，在身份核对后、POST transport 调用前同步复验，无异步间隙。

## 当前行为

- 确认框打开前同步加锁；同一操作的重复点击、改选环节及时间均被阻止。取消或原生弹框失败释放锁并保留输入，不发请求，不展示原始平台错误。
- 确认前后复核来源 session、actor、活动版本、所选环节与本人参加记录、取消/结束状态和读取新鲜度。确认期间状态改变要求重新核对，不沿用旧确认。
- 组件卸载、页面 hide/unload 均使旧操作代次失效；重新显示不能复活旧确认。等待身份读取期间发生这些变化，也不会新发写请求。
- 同屏申请、审批、邀请与参加变更相互禁用。参加变更自身的忙碌不使其 fresh 失效，因此正常确认仍可执行，不是把所有操作全禁用。
- 每次写入仍使用原持久化请求标识及原严格请求体。未知结果保留原请求，只能本人显式重试；不会自动重新退出、重新报名或生成新的费用规则。
- 请求若已经发出，页面隐藏/卸载不能保证服务器撤销。晚返回不调用旧页面的刷新/缓存确认，也不把旧结果显示为新账号或新活动的成功；原键保留，需返回原活动核对。这是“结果未确认”，不是“服务器没有写入”。
- 既有后端的本人权限、审批、人数、费用需重新核实提示、截止后参加状态变更与答卷不变规则均未修改。未增加退款、自动分摊或重新加入政策。

## 验证与回退

- 项目回归使用实际组件、`useStoredWrite` 和实际参加状态客户端；微信原生 API、读取和 HTTP transport 为离线替身。覆盖重复点击、取消/失败释放、会话/快照变更、hide/unload/unmount、已发晚返回、保原键重试及同屏正向互斥。
- 独立审计保留了三项原始确认失败、两项身份读取期间失败及对应修复后通过证据；不能据此声称真机或真实 PostgreSQL 业务已通过。
- 本次不改后端、contracts、Prisma 或部署。源码回退以此前 v10 独立快照为准；回退会重新引入这里已修复的确认生命周期缺陷，不宜作为正常运行版本。
