# 附近娱乐、运动场地的精确定位接入

2026-10-28，关联 Issue35 / WG-12。用户明确要求申请并接入精确定位；同一微信账号的 `wx.getLocation`、`wx.getFuzzyLocation` 已分别核对为“已开通”，隐私指引已更新。此前模糊版本的正常手机定位已获用户确认，不重复该项基础验收。

## 页面与授权

- 城市识别仍调用 `getFuzzyLocation`，使用 `scope.userFuzzyLocation`。城市仍需用户主动确认，手动选城、关键词搜索保留。
- “查看附近”调用 `getLocation`，单独核对 `scope.userLocation`。只在用户主动操作、会话身份和隐私授权通过后申请位置；进入页面、登录返回、切换导航不会自动获取位置。
- 新增“使用大致位置搜索”，由用户主动选择。精确拒绝、取消、不可用均不自动切换模糊定位，也不自动打开设置或重复请求；保留关键词及原结果。
- 两种授权分别读取、分别申请；打开设置只处理本次使用的scope。授权后提示再次点击对应按钮，不自动重放。跨账号、离页、旧请求返回的来源检查保留。
- 系统定位关闭、系统拒绝微信、微信小程序拒绝及声明缺失分别提示。系统已授权微信但仅允许大致位置时，精确操作提示在系统设置调整或主动选用大致位置；不会把这类坐标标成精确位置。

## 适配与构建

两种原生接口同时兼容回调及Taro返回Promise。精确请求使用GCJ-02、`isHighAccuracy: true` 和5秒高精度尝试时限；实际精度仍取决于系统、设备及环境。附近查询继续使用现有3公里范围及服务端地点接口，搜索距离为估算，不承诺步行距离、实时轨迹或米级精度。

服务端只收到原有契约允许的GCJ-02经纬度与检索参数，不新增速度、海拔、精度、后台持续定位或位置存储。没有API、数据库、活动流程、账号类目及供应商配置变更。

`app.json` 现在同时声明两种接口与对应权限。产物门禁同步要求两种声明、1–30字用途和实际编译后的原生调用；继续验证云登录、cloud-http目标、AppID及域名校验，未删除原有连接保护。

## 验证边界

相关离线回归226项通过，覆盖两种scope隔离、首次授权/拒绝、原生回调/Promise、缺少精确接口不降级、系统大致位置限制、旧会话失效、输入/结果保留及编译产物门禁。类型检查、构建、CI、开发工具和上传的最终结果分别记录在PR与Issue35。

接口开通不等于精确手机验证完成；此前用户回复“定位正常”属于旧模糊版本。本次精确功能须用新预览首次点击“查看附近”、允许精确位置后由手机确认。体验版、正式版未替换，整张Issue35保持开放。
