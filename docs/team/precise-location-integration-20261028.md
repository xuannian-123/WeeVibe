# 全小程序统一精确定位

2026-10-28，关联 Issue35 / WG-12。精确定位重申已获批，用户明确要求整个小程序使用精确定位。所有现有获取当前位置的入口统一调用 `wx.getLocation`，共用 `scope.userLocation` 的实际用户授权。

## 实现

- 全局城市面板“获取当前位置”和灵感“查看附近”共用同一适配器及权限检查。某个入口首次得到精确位置授权后，其他入口复用这份实际授权，不按页面另造授权状态。历史模糊位置授权不冒充精确授权。
- 仅在用户主动操作、会话身份和隐私授权通过后获取位置。进入页面、登录返回或切换导航不自动定位。跨账号、离页及旧请求返回检查保留。
- 拒绝或取消时保留关键词、原结果和手动选城/搜索；打开设置由用户主动点击，授权返回后提示重试，不自动重放请求。没有第二套模糊定位入口或隐式降级。
- 原生接口同时兼容回调与Taro返回Promise，使用GCJ-02及有5秒尝试时限的高精度请求。系统定位关闭、系统拒绝微信、仅允许微信大致位置、小程序拒绝和声明缺失分别提示；实际精度仍取决于系统、设备和环境。
- 城市识别后仍需用户主动确认；附近搜索保持现有3公里范围、关键词及服务端契约。只发送原契约需要的经纬度与检索参数，不新增速度、海拔、精度字段或位置存储。搜索距离为估算，不承诺步行距离、米级精度或实时轨迹。

## 配置及构建约束

微信开发工具实际编译校验精确与模糊定位接口声明互斥。新版 `app.json` 只声明 `getLocation` / `scope.userLocation`；源码移除 `getFuzzyLocation` 调用及模糊权限声明。产物门禁验证精确声明、1–30字用途及实际编译调用，并拒绝残留模糊声明/调用；云登录、cloud-http目标、AppID和域名校验保护保留。

接口资格属于整个小程序，各页面共用。平台开通与用户手机授权分别核对；没有API、数据库、活动规则、账号类目或供应商配置变更。

## 验证边界

本轮回归覆盖跨入口复用同一精确授权、首次同意/拒绝、设置返回、回调/Promise、缺少精确接口不降级、系统大致位置限制、来源失效、输入/结果保留与产物声明。最终检查数量、类型检查、构建、CI及预览上传回执分别记录在PR与Issue35。

此前用户回复“定位正常”属于旧模糊版本，不扩大为新版精确定位已通过。须用新预览打开任一定位入口，允许精确位置后由手机确认。既有基础双微信业务验收不重复；体验版、正式版未替换，Issue35保持开放。
