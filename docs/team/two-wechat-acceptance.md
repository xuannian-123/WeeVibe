# WEEGO 双微信实际验收

2026-10-25。本轮在一部手机上切换两个真实微信，已完成创建→两段申请→整体批准→双方关闭重开状态一致的主流程。用户明确取消双手机要求：双手机不列为本轮必验项、后续待办或交接阻塞条件。

## 范围与版本

- 两个不同真实微信，匿名记为A（本场管理者）和B（本场申请人）；本轮允许同机切换，不固定团队岗位。
- B已添加查看开发版、查看体验版权限；未授予后台管理或发布权限。
- 客户端为本轮临时预览，运行代码对应PR19（feature306c93a/main690ae1e）；API为同一代码树的独立HTTP函数，使用独立WEEGO PostgreSQL。后续文档提交不要求重新部署运行代码。
- 真实微信身份、幂等请求与审批权限均保留；不注入测试身份、不手写登录数据，不重置原AppSecret。
- 测试活动不作为真实邀约或订场。公开记录不填写微信号、OpenID、令牌或可访问活动的编号。

## 实际结果

| 内容 | 本轮结果与证据 |
|---|---|
| 登录与首页记录 | 用户确认两个微信可登录，B未出现A旧活动；独立PG核对到两个不同用户对应当前真实小程序身份 |
| 创建两环节 | 用户确认问题解决；PG记录管理者创建了打球、羽毛球两个环节，明确本人参加两段 |

| 整体批准 | 管理者批准该申请，PG事件revision3；两段容量均3、占位均2，各有管理者和申请人1席，均接受当前安排 |
| 关闭重开与页面权限 | 用户确认两个微信重开后均显示两段各2/3人、申请人两段已加入，申请人看不到管理审批区域 |
| 原请求恢复 | 用户确认原创建请求重试后显示时间已过，草稿恢复编辑；修复和云SDK证据见[恢复说明](./create-recovery.md) |

| 待审批阶段人数 | 本轮手机未单独记录人数是否增长；已有自动/真实PG检查，不补写手机观察结果 |
| 真机伪造管理API | 本轮未执行；页面区域不可见与服务端越权请求检查分开记录 |

数据核对为只读，没有代替用户申请或批准。确认的是本轮同机双微信主流程，不把达到最低人数写成已确认成局或已预订。
