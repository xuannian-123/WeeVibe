## 真实核心页面与设计批次建议

代码入口为 features/gatherings：designer（发起）、intake-editor（朋友表单/访谈）、questionnaire（团建问卷）、manage（内容整合/安排/候选方案/环节/定案）。正式活动仍在 activity-detail 和 arrangement-change，不能合并为一个假流程。

第一批建议聚焦朋友筹备三个状态：

1. 填写入口与轻表单：保留已存在的表单/访谈两种方式；活动昵称为首项，时间偏好、出发地、预算和活动偏好按真实步骤展示。个人预算、出发地仅本人可见，其他成员页面不泄露原值。
2. 方案选择：用现有多套方案及顺序环节，清楚排列时间、地点和费用；未核实费用不能写免费。组织者的“选定最终方案”和成员的浏览操作区分，不增加投票。
3. 定案结果：轻量完成感加当前安排与下一步；明确是筹备已定案，不显示“报名成功/已占位/正式成局”。定案后禁止新填、修改与生成；自己的旧填写仍可只读。

第二批再覆盖团建问卷/统计及正式活动编辑重接受。第一批确认后再实现对应内部页面，不一次定完所有页面。

外围适配清单：GO 不用历史补近期；三页中英大标题；我的简洁头像昵称和两卡；移除独立待办入口，保留后端规则；收藏白底爱心与撤销；灵感范围、手选城市不被定位覆盖；关闭/底部操作固定及键盘避让。缺人和管理者查看未确认仍需活动内提示归口，不能宣称消息已全覆盖。
