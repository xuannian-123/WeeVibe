# WG04 成局退出与原安排补位交付

更新 2026年10月28日。本轮从 main `49fd5e7` 接手，沿用 v38 已有功能，不重写已有身份、审批、席位或成局状态。

## 当前实现与本轮修改

- 既有服务及小程序入口支持人工核实和确认成局、分段退出、重申请及新增段申请。最低人数、有效接受、人工核实分别检查；人数达标不自动成局，满员和预订不替代成局条件。
- 退出与审批共用父活动锁和 Serializable 事务。只释放本人所选席位；5 人退至最低 4 人保留成局，4 人退至 3 人清除确认。补齐后仍由当前管理者明确恢复，原成员不重报。
- **本轮修复**：成员退出后重新获批参加，再重试旧退出请求时，返回最新参加记录及“原请求已处理”提示，不再把历史退出说成本次新退出，也不再次释放新席位。重试键和既有协议保持兼容。
- **本轮补齐展示**：详情区分待补位、待重新接受、待人工核实、待确认成局，显示达到最低人数的实际缺口；已截止提示开始前延期，已开始提示停止线上补位，后续开放段可继续单独加入。标签只解释服务端快照，不授予操作权限。
- **本轮补齐数据库验收**：新增 `scripts/check-wg04-postgres.ts` 并接入现有 CI，一次性本机 PostgreSQL 上执行真实服务、父锁、事务和失败回滚；不连接共享演示库。

## 验收覆盖

| 场景 | 预期 |
|---|---|
| 最低 4 人 上限 6 人 | 4 人且所有占位者接受有效、人工核实后，可由管理者确认 |
| 非主段退出 | 主环节不受影响，未退出段保留 |
| 主段 5到4再到3 | 5到4保持成局，4到3待补位，费用及安排不自动改变 |
| 新人只补主段 | 只占主段席位，原成员接受不重写，补齐不自动恢复成局 |
| 退出后回来 | 须新申请并获批；旧退出重试不撤销新席位，不制造新事件 |
| 新增组合中有满员段 | 整体失败，不部分占位，不丢已有参加段 |
| 保位待重新接受 | 不作为空位；全部占位者接受有效前不得确认成局 |
| 最后一席并发批准 | 至多一份批准成功，不超员 |
| 退出时事件写入失败 | 席位、确认、版本和幂等记录整笔回滚 |
| 越权 | 外人不能退出他人席位或确认成局 |
| 主段截止或已开始 | 不再批准加入主段，不关闭其他尚开放的环节 |
| 管理者退出所有参加段 | 释放本人席位，仍保留管理权，不自动交接或取消 |

## 本地或 CI 复验

明确准备名称为 `weevibe_acceptance_` 加字母数字后缀的本机隔离数据库，应用本分支已有迁移后，设置其 `DATABASE_URL`，运行：

```text
pnpm exec tsx scripts/check-wg04-postgres.ts --fixture-only
```

脚本拒绝远程地址与非验收库名，使用新建 fixture 用户及活动，不是真实微信登录。故障注入触发器在 finally 中移除；不清空数据库。CI 使用一次性 PostgreSQL 服务，任务结束随容器销毁。

开始后的线上核实或恢复成局规则目前仍按既有能力边界关闭，保留 `FORMATION_RULE_UNCONFIRMED` 提示；本轮不自行新增未确认的产品规则。不新增候补队列，不自动涨价、降低最低人数、处理外部订单或退款。
