# 自动偏好记忆第一阶段

本改动基于实际已发布源码 dd73df2，隔离分支 codex/preference-memory；不修改 D 盘现有成员工作树，不部署共享 API、不迁移共享库、不发布小程序。上游 main 当前仍为 9764e19；PR 以发布分支为基线，避免夹带其与 main 的全部差异。

## 范围和入口

复用 Gathering / GatheringMember、现有微信真实身份、填写及生成流程。只学习 play（活动类型）、travel（交通）、pace（节奏）的现有固定选项；排除“其他”和所有自由文本。开启后成功保存才产生来源任务，加入、未回复、组织者选择、方案生成不产生证据。未启用用户保留原流程。

“我的 → 偏好记忆”查看、手动纠正、撤销纠正、删除分类、清空、暂停学习、停止用于推荐。两个开关独立、默认关闭。首次填写可展开简短说明开启，无逐条保存弹窗。再次填写在已有空字段带入；用户已有值不覆盖。提示“已参考你之前的活动偏好，可修改”。本次不用可保留或移除未修改带入项，手改值保留。

自动带入值在 privateIntake.preference_memory 保存来源标记；提交时从公开字段剥离未修改默认值，只在本人回读还原。生成前由服务端按各成员的本次许可、全局推荐开关读取最小摘要，填充本次未明确指定类别。模型只有匿名 p 引用的必要 blocks，不含画像列表、来源历史、预算、出发地。历史块标为仅供排序、不带确定硬约束。复用原结果审查及地点、时间、未知项规则。

## 数据、版本和留存

新增 migration 20261030220000_preference_memory，历史迁移不变：

- PreferenceMemory：本人开关、学习 epoch、画像版本、删除屏障、手动纠正和聚合画像缓存。读取时按当前时间从有效证据计算，避免过期缓存被推荐使用。
- PreferenceLearningJob：本人、Gathering 来源、答卷版本、学习 epoch、状态、重试次数；不复制输入原文。
- PreferenceEvidence：本人、来源、类别唯一；保存规范值、来源版本、发生时间。同一来源修改替换，值不变保留旧时间，不因保存或使用次数刷新权重。

解释等级：本人纠正（撤销前优先）、较高可信（至少三场独立活动且衰减权重达门槛）、较低可信（仅参考）；不提供精确度百分比。证据保留180天、60天半衰期。缓存不代表额外原文副本。完成任务保留30天，失败任务保留以便排查；删除屏障随账户存续，不清除后自动回溯历史。删除分类/清空同时移除对应纠正和证据，并阻止删除前创建的筹备再作为该类来源。新筹备可继续主动学习。暂停保留画像，变更开关/删除/纠正推进 epoch，使迟到任务失效。任务和用户设置采用同一用户行锁，写前再次校验 epoch、开关、当前答卷来源版本。

## 接口和运行

GET /api/v1/preference-memory：使用既有 Bearer 会话，仅返回本人设置、画像及 pending/failed 数量；无 user_id 参数。
POST 同路径支持：

```json
{"action":"settings","learning":true,"recommending":true}
{"action":"correct","category":"play","values":["看展"]}
{"action":"delete","category":"play"}
{"action":"revoke","category":"play"}
{"action":"clear"}
```

由获准维护者将新迁移应用至明确目标后，在同一后端运行环境启动系统处理器（环境与 API 相同，仅服务端配置）：

```text
pnpm exec tsx scripts/preference-memory-worker.ts
pnpm exec tsx scripts/preference-memory-worker.ts --once
pnpm exec tsx scripts/preference-memory-worker.ts --retry-failed --once
```

必须由进程管理器持续运行，SIGTERM/SIGINT 安全退出；不依赖聊天会话。每批最多25个任务，每2秒扫描，失败指数退避1/2/4/8分钟，第5次进入 failed；日志只记录任务ID/失败类型，不打印输入或凭据。重试失败任务也会复核版本和来源。活动提交仅事务性入 outbox，模型和学习处理失败不回滚已提交活动；没有 worker 的环境只会显示待处理，不声称完成。

数据库最低权限：处理器需要上述三表和 Gathering/GatheringMember 读取，证据/画像/任务更新；不需要微信签名密钥或模型密钥。实际部署启动仍由维护者执行。

## 复现和验证边界

独立库（仅 localhost、数据库名 weevibe_acceptance_*，先执行所有迁移）运行：

```text
pnpm exec tsx scripts/check-preference-memory.ts
```

该脚本调用真实保存、任务处理和生成服务，验证开启→学习→第二场默认摘要→生成输入→本次修改覆盖→重复保存→删除重放→不同用户→无记忆流程，含同任务并发处理。模型为明确的 fixture provider；不冒充真实供应商。CI 已接到既有一次性 PostgreSQL 容器。UI B、真实微信 G、真实供应商、手机完整 A–H 必须分别验收。

本机初始复现：127.0.0.1:43188 无监听，连接被拒绝；没有此隔离分支后端配置或独立数据库，没有实际复现真实登录、筹备读取或供应商生成成功，不调整认证、不导出旧会话。部署版本依据发布回执 dd73df2/体验版1.8.0，本轮未独立查询云端版本。

离线初次全量：4437通过、3个UI断言失败，另3个suite缺少cloudbase依赖；随后离线安装两云函数依赖，修复UI回归，相关216项中215通过，最后剩余只读切换测试修复后表单92项全部通过。新增规则10项通过。最终全量及CI结果以PR检查为准，不将早期失败写成通过。

## 指标及限制

该阶段不能宣称推荐精确度提升。最多自动填入3类已有字段，但现有表单未因本改动取消必答校验，因此“必填字段减少”当前是0；具体少点选几项须通过实际用户记录衡量。自动带入项修改率、首轮接受率、协调轮次尚未接入持久统计/采集，没有真实反馈数据。不得用离线链路通过推算推荐提升。

自由文本模型提取、复杂评分、行为满意度推断和全面复盘均未实现。当前页面保留原五问，不自动跳过所有已知问题；只带入三类选项。画像列表需手动刷新查看异步处理状态。尚缺手机视觉核验与真实用户A–H演示，不能把服务端默认摘要回读当作已经看到了手机自动带入。
