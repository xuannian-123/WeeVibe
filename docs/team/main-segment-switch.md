# WG-05：直接更换唯一主环节首片

依据 [原规则第 89、90、95 行](../11-首版成局加入与补位规则.md) 与原 Issue #5：允许当前管理者直接选择另一有效环节为唯一主环节，原主转为普通环节；各段报名及安排保留，不强迫成员改变参加环节。新主必须按自身条件重新人工确认成局，不能继承旧主的确认。

本片仅实现**直接换主**，不同时取消原段、新增环节、调整人数、重排行程或修改时间地点费用。它不依赖仍待回答的最低人数变更核实策略，也不代表整张 WG-05 已完成。

## 已启用的范围

- 仅服务端验证身份的当前管理者操作。原创建者、普通参与者或旧管理者没有隐含管理权。
- 活动未整场取消，原主及所选目标均是同一活动内有效且未取消的环节，且均尚未开始；目标必须不同于原主。
- 新目标尚未开始、未取消是原规则要求。**原主已开始时本片暂未启用**，这只是本片实现范围，不宣称产品规则永久禁止该时段换主。
- 使用父活动锁取得最新状态后再采样时间；等待锁期间跨过原主或目标开始时刻不能按旧时钟执行。
- 报名截止不等于开始时刻，过了报名截止但尚未开始不单独阻挡换主。也不会因此重新开放申请、批准或延长截止。
- 目标不需要已满员或已成局才能成为主环节；缺人、待重新接受、未核实都保留真实状态，切换不把它们变成已满足。

## 精确的状态影响

只更新活动的唯一主段引用、`mainRevision` 和活动 `revision`，清空 `confirmedAt`、`confirmedMainRevision`、`confirmedPlanRevision`，并在同一事务记录事件及原请求去重键。

**不更新任何环节安排或 `planRevision`**，不修改最低人数、上限、时间、地点、费用、参加要求、核实或预订标记。不会把原主的核实/预订复制给新主，也不会把新主原有的声明升级为新的证据；既有声明仍属于原来未变的该段安排。

全部参与/占位、有效接受、待接受、退出、晚到及申请记录保持原样。只参加原主的人不会自动参加新主，管理者本人也不因换主自动占位。主段 A→B→A 每次都需新确认，不能因切回 A 复活旧成局状态。

切换完成后显示未成局。管理者应查看新主自身人数、成员有效接受及人工核实状态，再使用已有成局入口明确确认；不是本接口自动确认、核实场地或预订。其他未受影响段的状态按原规则展示。

## 权限、并发和原请求恢复

写入与审批、退出、取消、交接共用父活动锁与 Serializable 整事务；权限、来源 revision、原主和新目标都在锁后校验，失败全部回滚，不留下半次换主。

当前管理权限先于原 key 重放检查。原成功 key 只读取当前快照，不再次改主；例如 A→B 的请求丢回包后，活动又切为 C，恢复旧请求应看见 C，不能悄悄切回 B。此时“原请求结果已核对”不等于又执行一次原动作。旧管理者不能借历史 key 取回管理权。

客户端绑定真实活动快照的 session/actor 与原主、目标、revision；选择与明确确认分开，弹框前同步锁，取消/失败释放。最终 transport 之前再次检查身份、来源和页面生命周期，包含等待 `/me` 期间发生 hide/unload/unmount 的情形；同屏其他写入口互斥，不误锁自身正向流程。

未知结果保留本人原 body/key，不自动换键、覆盖或跨账号重放。畸形成功响应、错目标/身份、404 或版本不匹配不显示成功。已发请求不能保证撤销；晚返回不能更新新页面。恢复返回当前主段可能与原选择不同，界面必须展示当前事实而不是强制重试成原目标。

## 验收与未验证层级

后续匹配后端验收至少覆盖：

1. A→B，原主不取消；各段安排、版本、接受、占位、费用和核实/预订逐项不变，新主未成局。
2. B 尚缺人、待接受或未核实时仍如实展示；已有成局入口只在真实条件满足后允许人工确认。
3. A→B→A 不恢复任何旧确认；切换与审批/退出/取消/交接的两种先后顺序保持一致，旧页面/旧管理者拒绝新写。
4. 报名截止已过但原主/目标尚未开始可操作；锁后跨开始、取消、目标不属本活动、原主/目标相同或来源异常拒绝。
5. 同步双击、确认取消、身份读取等待中离页/换账号、旧响应、坏200，以及已成功原 key 在后续换主/开始后只读恢复。

项目测试使用真实服务、路由、客户端和组件配合明确的离线事务/平台替身；数量和最终通过情况以本轮冻结日志为准。它们不是 PostgreSQL 真实锁并发、微信原生或部署验收。此前50项 loopback HTTP属于上一轮构建，不包含本轮新换主路由，不重标为新接口实测。

## 回退

本片不新增表、迁移或依赖。保留上一源码/dist 完整包可关闭新增写入口，但**源码回退不等于数据库回滚**；已经确认的当前主段、版本和事件应保留，不通过重置字段恢复旧主或旧确认，也不能撤销已经发送的请求。不得为此回退到旧无条件答卷写服务；第9/10迁移和当前管理归属仍遵守既有安全回退要求。
