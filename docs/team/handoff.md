## 开发基线与调整空间

当前流程：发起活动 → 分享给朋友 → 本人选段并接受安排 → 申请 → 当前管理者整体审批 → 双方看到一致的参加状态。微信身份、管理权限、一次多段的容量事务及失败恢复已有实现。

这是本轮开发约定，可根据团队建议和试用结果调整。页面结构、表单、默认值、辅助功能优先级、地图入口及AI交互都继续讨论；规则也可重议，但须同步界面、契约、数据和验收。后端需要的数据字段不等于发起人必须逐项填写的表单。

产品应说清楚真实状态：申请不等于已加入，人数达标不等于已确认成局，未知费用不等于免费，地点资料不等于预订，未回复不等于同意。

## 本轮交接范围

1. 工程可按[开发指南](./development.md)运行。正式客户端、Next API、独立PG及真实微信登录已有证据；秘密与原服务不进入交接源码。
2. 首页能看懂用途、发起和继续最近活动。目前近期入口只覆盖此微信在本设备打开过的活动，不冒充完整跨设备列表。
3. 创建页先填名称、时间、集合点、人数及本人参加选择。单段不重复起名，结束日期默认同日，报名截止默认为本段开始时；特殊设置可展开。先完整预览，再明确确认；不代填实际人数、金额或参加意愿。
4. 详情突出行程、人数、费用、本人状态和当前管理者待审批；规则与版本收进更多信息，过时、保留席位和未核实仍须清楚。
5. 同机切换两个真实微信的创建→两段申请→整体批准→双方关闭重开状态一致及审批区域隔离已通过用户反馈与真实PG核对。本轮不要求双手机。
6. 留下可复现说明、已知缺口和任务入口。源码提交、临时预览、体验版上传及正式发布分别记录。

三页、工程基础及同机双微信主流程已可供团队试用讨论。不需要等地图和真实AI全部完成后才交给团队。
