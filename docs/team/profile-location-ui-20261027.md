# 资料编辑、定位授权与界面精修任务

2026-10-27。维护者明确本轮只改善界面、交互和视觉；创建活动与活动流程由其他成员继续设计，不在本轮调整。任务入口为 [Issue35](https://github.com/xuannian-123/WeeVibe/issues/35)，关联 WG-12。

## 已列入的界面精修任务

- 四板块分别记住滚动位置；同账号、同城市下保留浏览状态。
- 统一顶部信息层级、图标、大小、粗细和对齐。
- 改善文字对比度，规范字号、边距和模块间距。
- 统一卡片图片比例、长标题、元信息、按钮和圆角。
- 统一按下、选中、加载、空态与失败反馈。
- 检查弹层关闭、内部滚动、键盘避让、安全区、小屏和长文本。

以上保留为后续任务，不能因本轮资料整改就标记为全部完成。

## 本轮实现

头像：明确提供“使用微信头像”原生选择与“从相册自定义”两个入口，选择后先预览，明确保存后才上传。保留有大小边界的后端 JPEG 处理与当前账号校验；取消选择、上传失败和迟回不替换其他账号头像。昵称继续支持手动输入，增加“使用微信昵称”按钮聚焦原生 nickname 输入框，输入/确认/失焦均接收真实值。平台需要用户在选择面板或键盘候选中确认，不通过旧接口假称自动取得微信资料，见[微信官方组件说明](https://github.com/wechat-miniprogram/mp-user-avatar)。

资料：编辑页去掉个人封面、私人签名与私人补充介绍，保留一句话介绍、兴趣及逐项公开开关。历史封面和私密字段不因界面精简被批量清空或公开。推荐兴趣将咖啡替换为下午茶，并新增美食、唱歌、喝酒；本人原有自定义标签保留，仍最多六个。

扫码：移除首页按钮、原生扫码调用和对应等待状态。保留原生分享链接、活动详情外部入口和已有邀请权限；不修改活动业务流程。

定位：仅在主动点击城市定位/查看附近后进行，先核验身份，再检查隐私同意、系统定位状态、微信系统位置权限和小程序 scope.userLocation；首次明确请求授权，之前拒绝时提供原生设置按钮。打开设置不自动获取坐标或重放请求。不同账号、页面或城市来源变化后，旧结果不采用。拒绝隐私/定位、系统关闭或平台配置问题均保留手选城市和关键词搜索。

隐私弹窗通过原生 onNeedPrivacyAuthorization 与 agreePrivacyAuthorization 事件衔接；普通点击、渲染或迟回不代表用户同意，隐藏/卸载会拒绝仍在等待的请求。[当前 Taro 官方接口定义](https://github.com/NervJS/taro/blob/v4.3.1/packages/taro/types/api/open-api/privacy.d.ts)。

## 微信后台与实际边界

实际开发工具定位曾返回错误112：`api scope is not declared in the privacy agreement`，不是用户主动拒绝。前端已分别处理平台声明缺失与个人授权拒绝。

维护者完成微信公众平台登录后，核对 AppID 为既有演示小程序。后台原隐私说明只含剪切板与选中照片/视频，本轮保留原字段、联系方式、存储设置，补充头像昵称、位置信息及主动填写资料/需求的用途。保存后重新载入页面确认三项仍在。

后台的 wx.getLocation 也未开通。本轮已提交193字真实用途说明及两张实际开发工具使用场景截图，结果为“审核中”。没有申请后台持续定位、修改服务类目、重置密钥、付费或提交小程序版本上线。

代码及后台声明完成不代表接口审核通过。审核前定位可能仍不可用，不能用开发工具原生按钮调用成功或离线替身推断取得了真实位置。手机头像昵称选择和定位最终结果仍需分别确认。

## 验证记录

本轮253项受影响检查通过，包括真实组件配平台替身的手动/微信填入、取消/失败/换号回调，授权拒绝、后台声明缺失、系统权限、隐私原生同意事件和原有账户/消息/地点边界。旧扫码运行测试按已移除能力调整；原活动入口与邀请 codec 检查保留。旧组件测试的生命周期桩改为支持多个组件注册，未删除账户隔离或失败恢复断言。
