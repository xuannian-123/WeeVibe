# WG-08：活动图片分享卡首片（无报名二维码）

2026-10-27。独立模块起于 v29 基线，本包已在 v31（名单＋仅人数上限＋B1 v2）之上接入真实活动详情 Screen。只增加公开分享图模块、挂载及专项回归，不改 platform、共享契约、API、数据库、依赖或公开发布配置。**不是整张 WG-08 完成，不是已部署、微信原生通过或二维码可用。**

## 已做与明确边界

- 用户主动生成 → 单张公开行程图片预览 → 用户主动保存相册；不自动发送，不主动 `authorize` / `openSetting`，不下载远程头像或二维码。
- 明确白名单：活动名、公开各段名称/时间/地点/费用/人工核实与预订标记、取消状态、快照版本/时间、公开活动编号及已核验的 outgoing 邀请来源。无 viewer、成员名单、申请、答卷、个人出发地、路线、私密凭据或地点 provider URL；不截图整个页面。
- 各段保留顺序；文本过长用省略号表示摘要。超出 5000px 安全布局上限或无有效环节时明确拒绝单图，不悄悄丢段、不假称整份行程完整。该上限是本片保守保护，不是微信平台已实测上限。
- 时间统一显示北京时间 UTC+8；总价/每人/每小时分别标注；未知费用不是免费，报价非已付款。图片不显示实时席位或成局承诺，取消及变更以链接最新状态为准。
- 二维码 provider 尚未实现，不是只填密钥即可使用。后续已补 [公开 scene 入口](invitation-scene-entry.md)，仅经原公开邀请 GET 核验后打开当前活动，并未生成二维码。图片二维码状态仍为 `NOT_CONFIGURED`，页面及卡内显示“报名二维码暂不可用，请使用原生分享链接”。不造码、不假装活动编号可扫码、不复用技术预览码。现有原生分享功能不变。
- 原图仅是临时文件：不在存储中持久化图或会话，不宣称关闭预览能撤销已发生的相册保存。

## 生命周期与中断

每个组件实例、生成 epoch 使用独立 canvasId；绘制/导出/保存前、异步结果后均校验当前 session、来源、公开快照、fresh/busy、可见性和 epoch。A→B→A 不复活旧结果；取消生成忽略晚导出；双击只启动一次；旧 save 先 guard 再取锁，不能污染新面板；旧关闭 handler 读取同步 save 锁，不把已交给微信的保存假称取消。保存中关闭按钮禁用，native 返回取消/拒绝/异常/非标准成功均显示“保存未确认”，不自动重试或打开设置。调用已发后切页/换源只忽略旧UI结果，**不能撤回原生写入**。

## 当前接线与来源

详情页 `InvitationPanel` 后挂载唯一 `ActivityShareCard`，使用当前 detail、读取来源 session 与 read/login freshness；任何其他写入口 busy 时禁止新的生成/保存，旧在途结果失效。原生 `useShareAppMessage` 仍由既有单一控制器拥有，不新增或覆盖第二分享处理器。生成图片不会发报名、邀请创建、登录或远端查询。

`verifiedOutgoingInvitationId` 只接控制器已有 `outgoingInvitationId`：来自既有创建邀请源严格响应并核验 activity_id，且经过 InvitationPanel 当前会话/页面守卫。不会取 URL 的 incomingInvitationId 或另一个任意 UUID。模块只验证 UUID 格式，不自行联网核来源；无已核 outgoing 时图片省略来源，仍指向公开活动。图片中没有管理或身份凭证。

原生导出只接受本地路径（wxfile、本地绝对路径、无远端 authority 的 file:///、开发工具 http(s)://tmp）；拒绝 protocol-relative URL、远端 file authority 及控制/反斜线伪装。它不是下载外部图片的接口，也没有把普通活动编号当真实二维码。
