# WG-03 分段当前占位名单（窄首片）

依据保留的原 Issue 3（历史正文核对于 2026-10-26）及 `docs/11-首版成局加入与补位规则.md`：各环节独立名单，公共页面可看名单；未接受新安排仍保位，不当作已接受。此次不关闭整张 Issue，也不补“由谁邀请”的申请归因。

## 当前行为

- 活动详情中主动点击“查看当前分段名单”，只发只读 GET，不自动登录、报名、审批或定位。原活动详情接口未改；新 `GET /api/v1/activities/:activityId/roster` 需匹配后端部署。
- 仅展示本人填写的活动报名名 `Participation.displayName` 和 `已加入／保位待接受`。不是账户资料昵称；不查询个人资料、头像、出生日期、出发地点、答卷、晚到信息。响应不包含成员 userId、参与记录 ID、申请 ID、报名时间或退出时间。
- 待审批申请不占位，退出不再列入当前名单；同名两人仍有两行，空报名名如实显示“未填写报名名”，不根据人数补造名字。各段独立计算，一人参加两段分别出现。
- 尚未接受当前安排的 joined 记录继续占位，单独标明待接受，不变更费用、预订、核实或成局。
- 已取消活动或环节的历史名单本片暂不展示：明确 `members:null / counts:null`，不是空名单，不表示没有历史成员，也不删除任何历史。未取消的已结束活动仍可读当前保留的 joined 记录；不是完整出席或退出事件历史。
- 一次 RepeatableRead 事务读取版本、环节与全部当前占位报名名。完整读取上限为活动合计 2000 条当前占位和 2000 个环节，超过时明确 503 能力不可用，不返回截断名单或假全量。

## 版本、身份与失败

公共名单沿原公开详情的 optionalActor 入口：游客可读，但无效 Bearer 不降级为游客。客户端固定详情来源会话，最终 transport 前和返回后同步复验；跨账号、活动来源改变、hide/unload/unmount 的旧返回不显示。不会清除另一个新会话。

名单与详情必须匹配 activity revision、各段版本和人数；版本已更新要求先刷新活动，不能混合旧人数与新姓名。同版本仅时钟刷新不自动清掉已验证名单。页面不把旧接口 404/405、503、畸形 200 当“没有参加者”，不展示原始错误或响应正文。名单只在当前页面内存保存，不新增本机名单缓存。

## 验收与边界

本轮实际验证以最终日志为准：原旧 snapshot 缺名单的 before 失败及人数控制、服务/契约/客户端/实际 React 组件的离线替身回归、全量测试、类型和两端构建。名单来源查询和 DTO 的隐私白名单有专项检查；并非真实 PostgreSQL 隔离等级、微信原生或已部署接口验收。

在获准匹配后端验收时：A、B 同报名名参加不同段；待审批不出现→批准出现→安排待接受仍占位但单列→退出仅从对应段当前名单消失；取消段显示本片未展示历史。对过期详情、404 和超限分别验证，切账号及离页后不出现旧名单。不得在旧共享演示上为了测试而擅自创建真实记录。

沿用已有公开演示配置构建 `pnpm build:mini:demo`，不退回默认空 API。无新依赖、迁移或远端变更；原 schema/所有迁移和原 ActivityDetail 投影不变。源码回退不等于数据库回滚，不删除报名历史、不恢复旧权限或撤销已发请求。
