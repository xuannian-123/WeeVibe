# 本人资料：生日星座建议

依据已确认需求“可根据已填写生日计算并允许清空”。本片仅增加本地月日建议及主动采用/清空，复用原本人资料保存，不增加接口、数据库字段、权限、定位或供应商调用。

## 实际交互

- 生日仍可留空；已有有效生日时显示建议，但不自动填写星座，不覆盖已保存或未保存的手填内容。
- 修改生日只更新建议，已采用/手填的星座保持；只有本人点击“采用生日建议”才替换。生日同批次改变后旧按钮回调不能采用旧建议。
- “清空星座”只清该字段，不删除生日；清空生日只移除建议，不悄悄清除另行选择的星座。重新渲染/刷新不会自动补回已清空的值。
- 采用、手填、清空都只是当前编辑器输入，仍须点击“保存资料”。失败或未知响应保留本地输入，不显示保存成功；没有新增跨重启草稿承诺。
- 生日、星座仍为仅本人资料，不外发计算、不展示给活动成员、不用于性格/能力推断或成员匹配。日期无效、空值、未来日期不给建议；服务端既有校验继续生效。

## 同组件保存来源保护

独立组件探针发现，原资料保存等待期间卸载或 ownerSession 改变后仍可能调用旧 saved/close。本片在当前 Profile 内复核 mounted、最新 owner/session 和编辑来源代次；旧来源即使改回同值也不复活旧确认。finally 仅释放自身操作 ticket，不能解除新编辑器正在保存的锁。来源检查不撤销已发出的请求，不保证服务端没保存，只是不把旧返回确认到新编辑页面。

本片没有重写全局账户客户端或头像上传逻辑；不能把资料保存的上述证据推断为所有头像、hide/unload 或原生回调组合均已验证。

## 验收层级

纯函数覆盖12个月临界日前/当日/后一日、空/非法/闰日/未来值；实际 React Profile＋原账户客户端配合传输替身，检查采用/清空/手填、来源变化、保存未知、原响应晚返及锁归属。独立服务链和最终数量见交付日志。所有这些都是离线组件/函数证据；未调用真实微信、数据库、模型或地图，也不声称跨设备持久化已真机验收。
