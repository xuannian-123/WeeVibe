## 当前实现

GO：朋友出游入口保留「直接创建／先筹备」两条路径，团建进入现有筹备；中央按钮提供全部三种创建。首页只展示近期记录，完整活动、独立待办、保存邀请和手动打开入口保留在「查看全部／我的活动」。参与、待审批、组织与退出仍按服务端事实区分。

灵感：复用真实高德搜索、附近和收藏。新增来源中的区县及最多三张真实地点图片，未返回或加载失败时使用明确的淡彩占位；不把示例照片当场馆实拍。主动搜索／分类点击才请求地点，主动附近才申请定位。详情包含已有营业、费用和地图字段；「约大家去」带入按账号隔离的新活动草稿，只复制地点，不覆盖原草稿、不复制成员/同意或虚构已核实费用。图片字段及 show_fields 依据[高德搜索 POI 文档](https://developer.amap.com/api/webservice/guide/api/newpoisearch)。

消息：新增 `/api/v1/messages`，从本人报名结果、当前管理活动的申请、参加期间安排变化及取消/成局、自己的管理交接、可访问筹备进展投影。相同活动申请聚合，待审批数由数据库计数；同一环节旧安排变化不会重复计为多个当前待处理项。历史处理结果保留，阅读状态存入既有 MessageRead。逐条/全部已读先重新核验来源，只标记当前可见消息；不会批准、接受安排或交接。近期列表上限 100 条，角标与页内待处理数均对应当前列表，尚无无限历史分页。点击活动消息定位到对应操作区域。

我的：提供三种简洁默认封面及相册封面、现有头像上传、一句话介绍、推荐或自行输入的最多六个兴趣标签及排序。封面在服务器重编码为有大小/像素边界的 JPEG，移除原始照片元数据；不保存本机路径。MBTI、星座继续选填，生日建议仍需主动采用。主页介绍、兴趣、MBTI、星座默认不公开，逐项选择；原生日、性别、私人签名/补充介绍、收藏及活动记录永不从成员主页返回。

成员主页：独立 `/activities/:id/member-profiles` 与 `/:userId`，不放宽原 roster 接口投影。每次在 RepeatableRead 内核对当前管理者/有效 joined 席位；游客、外人、待审批、已退出及无席位旧管理者无权访问，取消活动/环节历史不通过此入口曝光。目标也须是当前组织者/有效成员。UI 入口在已验证名单中，支持本人预览公开视角。

## 登录与部署边界

沿用 PR31 的 automaticUser：验证并复用有效会话，仅无会话或明确失效时恢复；并发合并，网络失败不反复重登，不重放业务写入。主动退出的暂停标记持久化，显式登录才重新启用。详情见[原登录修复](home-automatic-login.md)。

本次复用现有 PrivateProfile JSON 和 MessageRead，不修改 Prisma schema、迁移文件、运行角色权限、密钥或云登录函数。新增服务端接口仍需发布同一 main 对应的 Linux API 包，客户端则重新构建公开演示配置并生成新临时预览。没有授权正式发布或更换原盆景线上版本。
