# 朋友出游 · 单一整理入口与依赖清理

2026-10-30。用户决定移除首屏“活动安排／其他明细”两个入口，并要求核对前后端及其他功能的连接。本说明取代同日三卡首屏、朋友独立安排和明细编辑的设计；首屏、选填专项文档保留作历史记录。此次结果仅为本地源码、构建与离线验证，没有上传或更新共享环境。

## 当前流程

朋友出游 → AI整理（填表或小橘头）→ 逐项填写 → 本人确定项核对 → 发起前预览 → 明确发起 → 分享真实活动 ID → 朋友提交想法 → 生成候选 → 成员选择 → 局头协调 → 每位成员明确确认 → 定案。

- 入口只保留一张整理卡，继续使用 C 字标、图标返回及现有视觉样式。总览不创建活动，唯一新创建动作在最终预览页。
- 同时移除朋友最终预览的安排／明细编辑按钮，以及发起后的管理页回入口。删除 `friend-details.tsx` 和专属废弃样式；`GatheringDetailsEditor` 类型及运行分支仅允许团建的 details／questionnaire，移除旧 plan 分支和跳转。
- AI 整理已覆盖发起偏好收集所需内容：活动昵称、明确日期，以及选填的有空时间、吃喝玩、想要／避开、个人预算与出发地。不能据此声称已自动确定具体集合地址、整段时间或公开费用；这些不是开始收集的前置要求，后续由候选与共同确认形成安排。
- 小橘头的原题目、顺序、解析函数与模型请求保持；本轮新增的是本机未完成进度保存，包括当前问题、未发送输入和原始预算文本。恢复不自动整理、读取昵称、定位或提交；完成或取消后清除未完成进度，正式偏好仍仅在明确确认后更新。
- 修正首页近期筹备把 `stage=arranged` 写成“筹备已定案”的既有问题。该 DTO 只表示已有生成，因此首页改为“已有方案”；实际定案仍以保存的最终方案与工作流为准。

## 数据和接口的边界

| 数据 | 本次处理 | 仍需保留的连接 |
|---|---|---|
| 新朋友创建 details | 从共享默认值重新构造，仅同步偏好日期及明确勾选的日期确定项 | 保持严格 create DTO；默认名称由后端使用“朋友出游”，默认筹备上限 50 含局头 |
| 个人预算／出发地 | 继续保存在本人的 intake.private | 不转成公开费用或集合地址，不送给整理／生成模型，不进入分享和公共成员内容 |
| 普通旧草稿的独立补充 | 同 actor 的本机只读归档，最终预览明确标注不带入本次发起 | 不再隐藏进入新请求；旧题目和答案可以查看，新创建的 questions／answers 一起清空 |
| 上次创建结果未知 | 原 body、原问题／答案和原幂等键保持，最终预览锁定编辑 | 只在用户点击核对重试时按原请求发送，不把新默认值套入旧 nonce |
| 上次公共明细修改结果未知 | 独立只读核对当前记录与原修改，读取核实后明确清除本机标记 | 该旧接口没有幂等键，不能盲目补发或改写 expected_revision；清除标记不撤销服务端内容 |
| 已创建朋友记录 | 保留服务端明细和真实历史公开参考 | 时间地点参与生成、人数限制继续生效、费用参与来源指纹；旧成员合法答案继续保留 |
| 团建 | 保留原 details、题目、候选地点、截止与编辑请求 | 不套用朋友新建清理函数，不删除共用字段／端点／数据库列 |

后端现有 `POST /gatherings`、成员 intake、generate、workflow 协议已能运行简化后的流程；本轮不新增 API、表或迁移。保留 `/details` 是团建和历史兼容的真实依赖，朋友当前界面没有新的明细编辑调用。历史 friend 自定义题不执行团建的 required 门槛，因此新访客空 answers 不会被必答题卡住；这不扩展历史题目的编辑能力。

普通旧草稿中若存在已移除题目的答案，单纯清空 details.questions 会令后端拒绝未知 question_id。本轮通过仅用于 fresh create 的 `friendIntakeFromDraft` 同时清空 answers，原本机草稿及原 pending 不被修改；已加入朋友保存自己的历史记录不使用该清理函数。

## 实际验证

- `vitest run gathering-`：25 个文件、645 项通过。包含真实填写／管理控制器、数据迁移和身份隔离、进度恢复、原问答、后端创建／人数／隐私及完整选择到全员定案。新增简化后端专项 10 项使用真实 service／generation／workflow 和明确的离线事务 fixture，没有连接真实 PG 或模型供应商。
- 新实际组件浏览器预览：78 项通过，覆盖 320／390／486 宽度、单入口、中途刷新、未发送聊天恢复、原问答至最终预览、仅最终创建、旧草稿题目／答案一起排除、原 pending 精确重试、旧明细只读恢复、成员／局头权限、明确手动整理降级。零页面错误、零真实外网请求。
- 分享参与 47 项、选择至定案 51 项、定案后完整安排 109 项浏览器回归通过；合计 285 项。本地预览有明确的身份／原生／网络离线适配，不冒充真实微信分享或真实活动写入。
- 小程序、Web 和测试 TypeScript 检查通过；公开演示配置的小程序构建通过。仍有既有资源大小告警：activity 313 KiB、common.wxss 326 KiB、common.js 375 KiB。
- 首页文案修正后，已有 `scene-home-scan` 与 `design-c-preparations` 共 5 项回归通过；不以列表的 arranged 标记推算全员确认。
- 全文依赖检查未发现朋友可达的旧安排／明细编辑入口、回调或路由。旧 start 预览生成／检查脚本转到新 intake；废弃 options 脚本已删除。旧 start／options 的在线本机页面转向当前预览，其旧可执行 JS／CSS／适配器也移除，历史检查／构建和截图记录以 superseded 标记保留。
