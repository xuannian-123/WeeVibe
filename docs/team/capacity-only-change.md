# WG-05：仅调整环节人数上限与 B1 v2

依据 [原成局、加入与补位规则](../11-首版成局加入与补位规则.md)“发布后新增取消与主环节调整”：新上限不低于当前占用（含保位）或最低人数；仅人数变化、费用与参加条件不变时，不要求成员重新接受。用户新提供的 2026-10-27 Issue 汇总沿用这些规则；其中历史勾选和基础验收不算本版实测。

## 此次完整的小闭环

当前管理者在活动详情明确选择未取消、尚未开始的目标段，输入新上限，确认后提交。报名截止不是上限修改截止，某个早段已开始也不锁定尚未开始的后续段。上限为正整数，最多 PostgreSQL int 范围；不得低于最低人数或所有 joined 占位（包括待重新接受）。待审批申请不占位，退出不占位。无法核清异常来源时拒绝，而不猜人数。

仅改变目标 `capacity`、活动 `revision`、可信操作事件和原请求记录。**不改变最低人数、费用、参加要求、安排版本、成员接受、席位、核实、预订、主段及已有成局确认**；不踢人，不替用户加入，不自动发通知。若要同时改费用/条件，不使用本入口；最低人数 writer 与核实策略仍未启用。

接口：`POST /api/v1/activities/:activityId/segments/:segmentId/capacity`，只接收 `idempotency_key / expected_revision / expected_capacity / capacity`。服务端从会话取 actor，父活动锁后检查当前管理者（先于旧键恢复），以锁后时间判断目标开始，并原子保存全部变更。原审批/退出沿同一父锁排序，故降上限不能绕过占位检查；这些锁与回滚目前由真实服务函数加事务替身测试，**不是实际 PostgreSQL 并发证明**。

成功原键重放返回现在的快照，不把后来上限改回去；交接后的旧管理者不能借旧键继续管理。未知结果保留原 body/key，手动核对恢复，不自动换键或声称未执行。已发送请求不能保证撤回。当前客户端显示来源会话、活动/段版本与页面代次绑定，确认前加锁，取消释放，最终 transport 前复验；已观察到来源 A→B→A 也使原操作失效，而单纯时钟刷新和自身 busy 不自锁。

## B1 v2：容量不是本人接受过的条件

原 B1 用完整安排（含 capacity）串联最低人数历史。仅修改容量却保留安排版本，曾使合法最低人数历史无法核验。因此此片同时升级可信历史读取与显示，但**不修改旧事件、不伪造最低人数 writer、不推断本人接受时的容量**。

- 服务端按活动事件顺序串联完整的最低人数事件与新 `segment_capacity_changed` 事件。容量事件必须仅 capacity 变化且 planRevision 不变；最低人数事件仍只能最低人数变化且 planRevision 加一。缺链、分叉、未知字段、链尾不一致均不开放重新接受；最多核验 500 条相关事件。
- 返回明确 `schema_version:2 / history_format:verified_v2`。`accepted_plan` 和参加要求差异只含需要接受的条件，不含容量；当前完整安排仍给出当前上限。
- `capacity_changes` 独立标注为非重新接受条件的操作记录；`history_anchor` 是首条可信事件前的链起点，**不是本人接受时点**，也不声称完整覆盖更早容量历史。客户端验证起点、两类记录混排后的完整链和当前尾值。
- 已接受当前安排时沿原策略不读历史。页面明确“本次不查询独立容量操作记录”，不能把空数组说成从未调整过容量。
- 新客户端严格兼容有效旧 v1，标为旧格式、独立容量历史未提供；不把旧 v1 补成假 v2。旧 v1 客户端应严格拒绝 v2，不显示成功，因此须配套升级前后端；不能把拒绝版本说成没有差异。

重新接受仍仅本人当前占位、目标开始前，报名截止已过不误挡；不自动成局。最小权限、公开字段和身份隔离不因 v2 放宽。详见 [B1 基础范围](arrangement-reaccept-b1.md)。

## 待获准环境的验收与回退

同一手机切两个已获准微信身份即可，无需两部手机：A 管理，B 占位；将上限降至含保位的占用数成功，再低一人失败且不踢人；过报名截止而未开始可改，开始后拒绝。原已成局、核实/预订、接受版本和费用保持原值。原审批与降上限分别先提交，检查原子结果。最低历史的离线 fixture 可验证最低变化→容量变化→继续审阅→本人重接受，不能在共享环境编造历史供演示。

本包仍按已批准公开演示目标执行 `pnpm build:mini:demo` 并过编译产物硬门禁；这不是新接口已部署的证明。旧接口 404/405、畸形成功或不匹配版本不算成功；保留未知原键。新 route 未做本轮真实线上或微信验证。隔离 worker 的本地开发服务器匿名拒绝日志只属前集成证据，不代表最终构建或认证业务通过。

无新依赖、表或迁移；第9/10迁移仍沿既有待核边界。保留 v30 完整源码/dist 回退。源码回退不等于数据库回滚，不能删除已写容量事件/原键、还原旧管理权或启用旧无条件答卷 writer。容量事件存在后，旧 B1 可能拒绝历史而不能继续操作；应停止不兼容写入口并配套恢复经审查版本，不通过删历史使旧客户端“看似正常”。
