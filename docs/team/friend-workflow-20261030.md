# 朋友出游 · 候选方案至全员定案

2026-10-30。本轮接在分享与首次参与之后，核对 96 屏中的 F12／F13，并将候选选择、局头协调、逐人确认、调整与定案按现有服务端 workflow 状态接通。这里只记录本轮局部结果，不代表 96 屏全部完成。

## 页面与交互

- 生成前使用 C 风格核对页，不再用原生弹窗承载完整流程；生成中、失败和原请求待核对均有对应状态。已知成员未提交填写、人数超过后端单次生成 50 人限制时，不发送生成请求。分页未读全时不宣称已经收齐，最终由服务端校验。
- 候选方案使用简要卡片、顺序环节与完整详情；成员可以多选，也能明确提交“都不合适”的意见。浏览详情不发送业务写入，选择偏好不等于最终同意。
- 局头进入单独的协调页面，按成员填写数、已选人数及工作流版本判断能否发送。局头也需要明确确认自己的协调方案，不能直接跳到定案。
- 确认页只展示本轮提议的方案。本人确认使用本人真实 confirmation 版本；已接受但尚未全员完成时仍能提出调整。有人拒绝则回到协调；重新发送会清空之前的确认，要求全部成员重新确认。
- 全员确认后的结果、完整安排与本人只读内容统一 C 风格。显示后端保存的最终方案，不自行推算定案，不表示已预订、付款或正式成局。
- 删除管理页的直接 `/finalize` 调用，以及不可达的旧朋友流程展示分支。没有 workflow 的历史推荐只读，需重新生成后进入共同确认流程。移除已不引用的旧方案与结果样式文件。
- 内容整合可以返回当前工作流，包括定案后再次查看结果；不会回到旧的朋友管理菜单。

## 前后端核对

继续使用原有 `generate` 与 `workflow` 端点及共享契约，不新增状态、接口、数据库迁移或生产后端规则。保留原请求的幂等键、会话和版本边界。

- 方案选择使用 own_selection.version，提议使用 workflow.version，确认使用 own_confirmation.version 与 proposal_version。
- 对生成与工作流回执补充业务校验：缺少实际选择版本、缺少最终方案、最终标识不匹配、仍开放修改等情况，均保留原请求，不展示确认成功。
- 幂等重试按原内容发送；后端可能返回更晚一轮／更新一代的当前快照，前端接收权威新状态，避免因为原 generation 已变更而无法清除已完成请求。
- 最后一次确认回执丢失时，刷新读到已定案后仍可核对原请求，防止遗留待确认记录没有处理入口。
- 公共协调文字采用与后端相同的隐私字段规则；个人预算及出发地点留在本人填写，不进入生成请求。
- 小橘头的问答顺序、回答解析和模型调用未改动。
