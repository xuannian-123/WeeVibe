# WG-10 一键再约：历史安排复制为独立本机草稿

本片对应 Issue #10 / WG-10，与 [第11号规则](../11-首版成局加入与补位规则.md) 的“一键再约”范围一致。**复制不是发布，不是邀请，也不代表新日期已经核实或预订。** 最终代码、测试数量及冻结哈希以交付日志为准；以下手工步骤尚不是微信真机或真实数据库验收记录。

## 当前启用范围

- 仅服务端识别的**当前管理者**，源活动未整场取消，且全部环节有有效时间并已结束。
- 选择未取消的历史环节，至少一段；多段时重新选择新主环节。取消段不进入模板，界面须说明排除数量。
- 其它身份、尚未结束/进行中的来源、整场已取消来源尚未启用。这是首片功能范围，不是原产品规则禁止复制这些活动。
- 不新增表、迁移或供应商实现；本轮工具/测试未调用真实模型或地图。用户仍可主动使用原地点选择器，不自动查询/定位，不新申请权限。只读来源接口不修改原活动，不授予新席位。

## 复制什么，清除什么

可复制活动名称及所选环节的类型、名称、顺序、最低人数、人数上限、公开集合地点名称/地址、参考费用与口径、参加要求。它们仅是待复核文本，不是新场次事实。

新草稿重新生成环节引用，**全部日期、开始/结束时间、报名截止、本人参加选择和昵称都清空**。地点/费用需在该段新日期和开始/结束时间完整合法后逐段主动核对；修改日期、时刻或对应地点/费用内容后原核对失效，改回旧值也不会自动恢复。核对只是用户确认已查看，不是程序验证营业、可订或实际价格。原日期无论是否有效均不继承；新编辑器使用当前界面明确显示的 Asia/Shanghai 时间。

不会复制旧成员/申请/同意、席位计数、接受/安排版本、旧邀请或链接参数、幂等键、核实/预订/成局状态、个人出发地点、路线、私人资料或需求答卷。来源活动/环节 ID 只用于有权读取和选择的内部绑定，不进入新活动创建 payload；旧 source_url 或地图选择凭据不继承。

## 本机保存与未知结果

1. 主动进入来源选择，选择历史环节；此时不创建服务器活动。
2. 明确点击“复制到本机新草稿”后才建立再约草稿。普通朋友活动草稿、未确认发布请求和已完成记录保持原样。
3. 再约使用本人账号和来源隔离的独立存储。已有同源草稿先恢复，不静默用来源刷新覆盖；同身份重新登录可恢复，换身份不显示或重放别人的草稿。
4. 补齐新时间/截止，逐段核对地点费用，明确本人是否参加。再约模式不会默认使用旧成员或本人旧参加选择。
5. 先预览，再主动确认创建。沿用原创建服务的新请求标识，生成全新活动和环节 ID；之后才可在新活动里主动邀请朋友。
6. 创建结果未知时保留原请求和键，不通过重新复制生成第二次发布。合法、同身份的原 pending 优先人工恢复；旁支草稿或完成入口损坏仅阻止新创建，不能挡住已验证原请求的恢复。原 pending 自身损坏或无法读取时仍暂停发送，不猜内容。原键核对可能首次执行，也可能只读恢复此前已创建活动，不能承诺所有重试都不会写入。已发送请求不能保证撤销。

新发布在预览以及该次**首次活动 POST 发出前**同步复查客户端日期/截止，避免身份读取等待时已过期仍新发。此项是再约客户端首发保护，不改变原创建后端对“只组织不参加”的时间政策，也不能保证请求在网络传输中不跨界。既存未知请求的人工恢复不因日期过期而丢键；若此前已创建则恢复原活动，若此前未成功则仍按原创建服务规则核对并可能首次执行，不宣称恢复一律只读。

来源读取/导入绑定原会话和活动，返回前复验；页面隐藏、卸载、来源或账号切换后，晚返回不导入或落盘。复制成独立本机草稿后，不会持续同步或修改原历史活动。新活动的管理权来自原创建服务，旧来源管理权不隐式继承。

## 维护者最短验收（需另行获准的匹配后端）

- 准备管理者 A 的已结束、未整场取消、多环节活动；在源中放置旧核实/预订、原成员/申请、历史邀请及本人私人字段哨兵。
- 非管理者、已交出管理权的 A 及未登录读取来源应拒绝；取消/未结束来源说明本片未启用。不泄露模板或私人值。
- 只选两段，重新选主；检查新日期/截止/参加/昵称为空、原 ID 与状态不进入新 payload。未勾地点/费用核对或未填新时间不应发布。
- 空日期不能勾选核对；修改已核对日期/时间/地点/费用，相关核对状态应失效；返回、刷新、换账号、延迟来源响应都不能悄悄覆盖已有新输入。
- 复制期间检查普通草稿/pending/completed 字节不变；重复复制和来源刷新不能覆盖未确认发布的原 input/key。
- 手动补齐后确认发布，新活动 ID 与各环节 ID 全新；默认无旧成员席位，只有用户本次明确勾选的本人参加可新建；原活动、历史、费用、预订不变。旧创建与 AI 填表仍按原流程运行。
- 首次发布等待身份读取时跨过截止，应在活动 POST 前拒绝；已发出的请求迟回不能仅因后来过期而伪报未成功。404/405 或畸形成功响应不导入假模板、不显示已发布；未知创建返回保持可恢复原键。

离线 fixture 只能验证真实函数编排、查询/投影和组件边界；它不证明 PostgreSQL 真实并发、微信存储/生命周期、地图或模型能力通过。旧 46 项 loopback HTTP 不包含新增再约路由，不应当作其实际 HTTP 验收。

## 回退

保留本片前完整源包和原普通草稿命名空间。本片无迁移，源码回退仍不等于撤销已发请求或删除已创建活动；不删除任何服务器历史或旧本机草稿。原有第9/10条迁移及管理归属保持原安全回退要求，详见 [答卷 CAS](requirement-answer-cas.md) 与 [管理交接](management-handover.md)。
