# 需求草稿：未知创建结果与同身份重试

## 已复现问题及修复

旧表单只将网络错误/5xx视为不确定。发生“创建可能已提交但响应丢失→重试在幂等查询前被401/403/429拒绝”后，它错误地丢弃原创建键、解锁表单；第三次提交会生成新键。对未绑定原活动的团建私有草稿，这有重复创建风险。

本轮复用原工程 `write-policy.uncertain`，不再另造较窄的分类：网络/未知响应、5xx、401/403/429等保持原幂等键和原内容；识别为确定的业务拒绝后才释放编辑锁。重试始终由用户主动触发，不因重新渲染自动发送。

保留原请求不等于可换用户重放。编辑器绑定打开时会话，账号变化或退出后隐藏原输入，不使用新账号发送原稿；请求回来时也重新检查会话和页面是否仍存在，避免旧成功回调更新新页面。会话更新后需重新打开并核对本人服务器草稿。

这项修复保留的是当前编辑器内的原请求；**没有新增跨关闭/重启的本地草稿持久化**，不能承诺未保存文字在任意关闭后都能恢复。服务器已经确认的草稿仍由原有列表与本人权限恢复。

## 未配置与404/405

无结构化业务错误的404/405可能来自旧后端、路径/请求方式/版本失配。新提示要求核对API地址和后端接口版本，仍标记 `INVALID_RESPONSE` 和“写入结果未确认”，不说一定已写入或一定没写入。

结构化 `NOT_FOUND` 仍是资源不存在/不可访问；`NOT_CONFIGURED` 与 `UNAUTHENTICATED` 保持区别。不展示原始HTML、完整错误体或私有答卷，也不通过换凭据、伪登录或本地假活动绕过缺少后端。

## 验证范围

3项修复前实际React组件探针失败（401/403/429后新键与原键不同），修复后同身份原请求保持一致。新增恢复回归覆盖更多未确认状态、换账号/退出隔离、卸载/晚到响应、确定拒绝解锁、成功后结束不确定状态，并检查缺接口提示不会改变业务错误与结果未确认语义。

本轮无数据库迁移、真实账号操作、后端部署、付费调用或微信真机验证。最终全量/类型/双端构建以交付日志为准。
