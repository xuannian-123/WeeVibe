# 移除一起团建（2026-10-30）

本轮以已上传体验版 1.8.0 的 `dd73df2` 为基线，仅移除一起团建产品能力。此文记录代码变更，**不代表已更新共享 API 或体验版**。

## 前后端范围

- 首页、创建弹层、关于页移除团建；首页朋友出游卡片改为单列。旧 `new=team` 路由不登录、不提交，显示失效入口。
- 删除团建问卷页面、活动安排编辑器、旧 TeamCreate、旧首页、专用图标及无引用样式；朋友出游继续使用已确认的单入口和偏好确认后发起流程。
- 两套历史数据入口（`gatherings` / `requirements`）的创建契约仅接受 `friend`；读取、写入、生成、协调、定案、订阅授权及重放均拒绝团建。
- 首页近期筹备、全部列表、账户消息和消息中心在数据库查询中先限定 `friend`，再分页。客户端兼容旧服务混合列表时只去掉 `team` 行，其他非法数据仍拒绝；单条团建响应不改名为朋友出游。
- 团建不再产生通知事件；通知队列领取查询过滤历史团建，已有订阅意图不会被消耗。已经发出的微信消息无法撤回，其旧链接由新后端拒绝。

## 保留项与原因

- 不清理共享数据库，不修改迁移或公共数据表。历史团建行保留为不可访问数据，避免误删外键关联内容；没有保留可用的团建业务入口。
- `TeamDraft` / `validateTeamDraft` 是旧命名，但同时用于朋友筹备、正式活动的需求收集与 AI 契约，保留这些共用定义。
- 朋友出游旧草稿里的 `questions` / `candidate_places` 仍用于只读历史记录及原请求重试，不能按名称批量删除。朋友出游幂等键、草稿键和来源指纹保持兼容。
- 小橘头的 `organize` 提示词与实现、朋友偏好访谈逻辑不改；仅从行程生成提示词去掉团建统计输入说明。
- 其他正式活动、报名、灵感、账户功能继续保留。

## 验证及发布边界

本地类型检查、单元/UI 回归、小程序构建与模拟器预览按本轮最终结果记录。新增 `scripts/check-team-retirement.ts` 使用 101 条旧团建筹备和 101 条旧团建需求记录，验证 SQL 分页前过滤、读写拒绝、消息读取隔离及朋友记录不变。通知集成脚本验证历史队列和原订阅授权重试。

本轮不部署。后续维护者更新共享版本时需先部署本轮 API，再上传对应小程序；只更新前端不能关闭旧客户端的团建接口。本轮不需要数据库迁移或微信隐私权限变更。
