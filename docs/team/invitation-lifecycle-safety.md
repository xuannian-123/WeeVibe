# 可转发邀请的确认与生命周期

## 修复前证据

实际 `InvitationPanel` 与实际邀请客户端、替身 Taro/HTTP 复现五项失败：在确认框或身份读取等待期间 hide/unmount，旧操作仍会新发 POST；已卸载后晚响应仍调用分享来源回调。不是创建了新群规则，也不是服务端越权证据。

## 最小边界

- 详情读取的 session 作为来源传入，与显示 actor 一起核对。最终 POST 前同步复验页面代次、actor/session、活动/来源 ID、活动版本和权限快照；不会在异步身份核对后改用新账号的 token。
- 创建确认前同步锁定；重复点击只开一个框，取消/原生错误释放锁，仍可重试。保存邀请复用同一生命周期 guard。hide/unload/unmount 使旧代次失效，重新显示不恢复旧确认。
- 邀请自身忙碌不自我判定为 stale；同屏申请、审批、退出/晚到在此期间禁用。正向创建、保存和取消后的继续操作也测试，避免只靠全部禁用取得安全测试通过。
- 创建响应必须属于原活动；读取和保存响应必须属于请求中的来源 ID，保存还须匹配原活动；UUID 大小写规范化。不能把合法形状的错目标响应当成功，不展示原始不可信返回。
- 已发请求无法保证撤销。晚返回不更新新页面分享来源或“已保存”；未知结果不声称未写入。回到原活动核对后可显式重试；沿用服务端原本按活动+邀请人唯一来源、本人+来源唯一保存关系的语义，**未新增客户端持久化请求键，也不声称跨重启恢复原请求**。
- 邀请仅表明可转发来源，不验证指定收件人或当前微信群成员，不授权查看私人答卷，不等于报名或授席位。原后端权限、已参加/管理者可建来源、取消活动限制和所有审批规则均未改变。

## 验证与回退

本轮为本地真实组件/客户端配合原生和 HTTP 替身、单元测试、类型及构建验证；真实微信分享、原生生命周期与真实数据库业务仍未验。原五失败保留为历史证据，不算当前测试通过数。相邻入口未覆盖项见 [统一安全矩阵](write-boundary-matrix.md)。

保留 v11 完整源码/dist 快照及本轮受影响原文件备份。源码回退不等于数据库回滚，不撤销已发 HTTP；回退旧客户端会重新引入上述生命周期缺陷。本轮无数据库/后端/contracts/配置/部署变更。
