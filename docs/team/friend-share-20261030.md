# 朋友出游 · 分享与首次参与核对

2026-10-30。本轮承接偏好至发起的连续页面，核对设计 F10、F11、F11A 与相关登录、入口异常和提交恢复。

## 行为与页面

- 发起成功页提供原生 `openType="share"` 的“分享给朋友”和“看看大家的想法”。页面级分享回调绑定经原创建请求验证的新活动结果，即便当前路由仍是 `new=friend`，也分享实际活动 ID。分享路径只包含活动 ID 与 `entry=share`，保留安全分享图。
- 分享数据绑定当前 actor/session。切换账号或收到旧请求的晚到结果时，不沿用原账号的新建分享目标。
- 打开分享先核对微信身份、读取指定活动；登录后保留原入口。无效 ID、同时传入 ID 与 new 等冲突入口不进入创建或读取流程。加载、登录、读取失败及无效入口采用 C 风格状态页。
- 未提交的朋友先填活动昵称与偏好，展示当前活动和发起人。打开链接、切页、整理与确认确定项均不加入名单；最后以“确认参与并提交”调用一次 intake，携带 `join_if_needed`，沿用后端原子加入及保存。已有成员提交只更新本人填写，不重复加入。
- 已填写者再次打开分享直接进入 C 风格内容整合；局头从其他入口进入也直接看内容，不保留旧的双入口菜单。普通成员不展示生成操作，局头仍需明确确认后生成，权限与来源均按服务端数据判断。
- 内容整合只显示服务端给出的公开成员内容；预算、出发地只在本人填写中查看，不进入分享或 AI 整理请求。不新增正式活动报名、容量占位或自动接受行为。
- 仅在响应确认成员身份、本人答卷存在、本人版本至少达到本次提交版本后报告保存成功。无效回执或网络结果未知保留原请求，进入 C 风格待核对页，重开不会自动重发，明确重试沿用原内容与幂等键。

## 实现边界

新增 `entry-state.tsx`、`friend-hub.tsx` 和样式；继续由原 Page、Designer 与 Manage 控制器处理身份、版本、请求、分页和业务动作，展示组件不另造活动状态。小橘头问答顺序、回答解析和模型接口保持，调整的是参与者最终提交文案与已确认保存后的去向。

使用现有 GET gathering、POST gathering 和 POST intake 协议及共享契约，无数据库迁移、新接口或共享后端更新。本轮未完成候选方案、协调及最终定案整段的重新设计。
