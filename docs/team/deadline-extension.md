# WG04/WG05：仅延长报名截止与 B1 v3

依据[第11号规则](../11-首版成局加入与补位规则.md)第18、40、77行：报名截止限制该段新申请和批准；当前组织者可以明确延期继续补位，但不能绕过开始或取消。原成员重新接受的时限是该段开始，不是报名截止。本片不依赖最低人数核实或取消问卷两条待答规则，也不代替这些规则作决定。

## 只延长，不改参加安排

当前管理者明确选同活动未取消、尚未开始的环节，查看旧截止并输入带时区的新截止。新值必须晚于旧值、晚于服务端检查时刻且不晚于原开始。旧截止已过可恢复后续申请/批准；未过时也只能向后延长。它不是缩短截止、改开始结束或开始后例外入口。主段开始不误挡另一个尚未开始的后续段。

POST `/api/v1/activities/:activityId/segments/:segmentId/deadline` 仅接收原请求标识、活动来源版本、原截止、新截止。服务复用原父活动锁、当前管理者权限、Serializable整事务及幂等；锁后及写入前重取时间，失败全部回滚。当前管理权限先于成功旧键恢复；旧管理者不能借成功key再次管理。正常只更新该段deadlineAt、活动revision、不可变延期事件与请求记录。

**不改变**开始结束、地点、费用、要求、最低人数、上限、planRevision、成员已接受版本/时间、席位、申请状态、核实、预订、主段、管理权及成局确认。不自动批准旧申请、不自动加入或恢复成局。新人仍走原整份申请审批；该段满员依旧不可加入，其它段按各自条件判断。不改问卷/答卷、需求收集截止或定案；不通知、扣退款或退订。

## B1 v3：报名窗口不冒充本人接受过的条件

旧B1完整安排含deadline，直接改数据库字段会让已有可信链与当前尾值不一致；已接受当前版本的投影还会把新截止错误归入旧接受。不能只增加writer而跳过此依赖。

新服务输出明确v3：当前完整安排保留当前人数上限和截止，`accepted_plan`与接受条件差异不含capacity或deadline。容量和延期为独立操作记录，**不声称成员在同一个planRevision的实际接受时点曾接受过某个运营值**。当前条件已接受时沿原策略不查独立历史，空操作数组明确是本次未查询，不代表从未调整。

服务端先按三类不可变full before/after事件核完整链：最低人数实质变化增加planRevision；仅容量和仅截止变化保持planRevision。旧事件不改写，未知/缺失/分叉/超限/不合法字段变化/链尾不符均不开放重新接受。活动revision须严格递增且唯一，但不要求连续整数，因为其它段和管理操作也会产生合法记录。

客户端v3同样混排验证：anchor是首条可信链起点、不是接受时点；容量/截止的交错状态与每次最低变化的当时值都核对到当前尾值。旧v1/v2先由原严格schema校验，再以明确legacy格式显示，不假补独立延期记录，不把旧deadline投影变成v3已接受条件。

新客户端兼容有效旧协议；旧客户端应拒绝v3而非假成功，因此升级需匹配前后端。原旧格式不支持新延期历史不能靠删事件或放宽校验“恢复”。本人重新接受仍仅原占位、目标开始前；报名已截止不误挡，席位保留且不自动成局。

## 确认、未知结果与来源

页面确认前同步加锁，取消或失败释放；实际发送绑定原actor/session/活动段来源与页面代次，最终transport前再核验。已观察来源A→B→A也不是原操作。普通时钟刷新不丢未保存输入，自身busy不使正常发送自锁，同屏其它写入互斥。

首次新请求在等待身份核验时跨开始或新截止，不应继续首次发POST。已经发出的请求不能保证撤回，也不能因为响应晚于开始而丢弃原成功记录。未知结果保留原body/key供手动核对；原key可能首次执行，也可能恢复此前成功的当前快照，不能一概说重试不写。已成功key后期核对不把后来截止回拨；退出/交接/取消后的当前权限和状态仍以服务端为准。

旧接口404/405、缺配置、畸形或不一致成功不冒称延期成功，不静默换body、去掉旧截止或生成新key。相同下一revision的首次确认结果应匹配本次目标新截止；较新版本允许返回后来合法改动的当前状态。版本已变化时须刷新，不让旧来源继续覆盖。

## 验收与回退

最终通过数量和冻结哈希以交付证据为准。实施前已用不可变v36实际Screen与真实B1服务函数、离线数据库替身记录缺入口/链不兼容，非真实数据库故障。新writer、审批顺序、混合版本历史、旧协议、实际组件/客户端/路由/服务的替身链及全量/类型/两端构建是离线验收；不证明PostgreSQL锁、微信操作或当前云服务部署通过。

无新表或迁移，保全部11条既有迁移不变；第9/10/11真实应用仍待核。公开demo配置不改，小程序必须通过实际cloud登录/transport编译门禁。此片不部署、不读取凭证、不访问被拒路径，不混未签二维码候选。

保v36完整源包回退，但**源码回退不等于数据库回滚**。新延期事件存在后旧B1可能拒绝其历史；必须停止不兼容入口并恢复兼容服务，而不是删除事件、改旧deadline/旧接受或恢复旧管理归属。已发请求也不会随源码回退自动撤销。
