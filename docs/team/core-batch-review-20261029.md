## 最新规则（覆盖旧资料门槛及匿名编号方案）

- 出发地留空表示愿意配合其他人的安排；预算数值与备注均留空时也表示愿意配合。已填写的限制保持原值，零元不按空白处理。
- 愿意配合是偏好，不等于免费、正式报名、自动接受未来安排、自动占位或代替他人同意。私密原值不改为公开。
- AI问答按钮改为“小橘头（AI问答）”。
- 取消账号头像与昵称门槛，同时保留可信微信身份和业务权限核验。所有填写者在问卷/需求开始填写前设置本次活动昵称；团建局头在发出问卷前也设置本次活动昵称。
- 团建编辑器每题支持折叠；题库加入默认折叠；新建和题库题默认必答，可手动关闭。新建题先展开便于编辑，历史题目既有必答开关不自动改写。
- 活动成员展示使用活动昵称，不显示编号、内部user_id或成员主页；本人“我的”中的账号头像昵称仍可自愿保留。

## 合并顺序与仍待完成

1. 用户按组集中确认，并按页面编号提出修改。新规则已经明确，无需对相同规则反复询问。
2. 一次接入剩余已确认布局，统一复用表单、弹层、状态组件与既有接口；同步移除服务端头像昵称前置断言，补团建活动昵称及默认必答/折叠逻辑。
3. 对门槛、昵称投影、隐私、默认值、问卷校验和业务链路做必要回归及构建；复核新PR/CI后合并源码。
4. 共享API部署、迁移（如确有需要）、微信临时预览或体验版分别按后续明确授权处理。

新规则目前仅进入批审规格，尚未修改生产业务代码；当前线上仍可能出现旧头像昵称门槛。不能把本地原型写成新规则已上线。

未扩展：自动把筹备转成正式活动、投票、聊天、成员主页、自动预订/退款、开始后尚未启用的取消/换主等业务。现有旧正式活动需求模块保留为附录，不与新筹备重复建一套。

四导航与工具页仍按已经确认的 team-preview/dist 适配，本批不重新设计这些页面；它们与内部流程一起完成接入和统一回归后再作为剩余前端的合并批次。头像昵称在“我的”仍为自愿编辑，不再作为使用入口门槛。
