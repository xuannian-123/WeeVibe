## 已确认的产品方向

1. 导航：GO／灵感／消息／我的，覆盖早期首页／灵感／活动／我的。中央创建按钮等细节未在本轮单独确认。

3. 团建不强制验证微信群成员：组织者分享入口，参与者登录后可填需求；正式参加走报名审批。公开入口可能转发，不能当作原群成员身份证明。
4. 隐私按下表执行；接口、分享和 AI 解释与页面使用同一权限，不能仅前端隐藏。

| 信息 | 组织者 | 其他成员 |
|---|---|---|

名单：组织者和本活动已加入成员可查看分段报名名，游客及尚未加入者仅看人数。

## 已实施的产品适配（对应原包差异）

- 需求 API 管理者逐人仅返回时间、意向环节与协调所需身份；预算、偏好、自由文字、其他题目原文及私人出发地不向他人返回。成员可查看同一汇总；本人原始答案仍可恢复。
- 增加选填的数值预算上限、兴趣标签、需要遵守的限制标签。汇总只提供预算上限范围和选项计数；旧文字只计填写数，不推断金额、不原文外显，也不将填写数冒充需求已满足。
- friend 无 activity_id 可建立筹备；第 12 条兼容迁移仅修改原 CHECK 约束，不改旧 SQL 或创建假的正式活动。筹备发布仍须标题、明确未来填写截止；开始时间和候选地点可不确定。
- 团建可分享发布、填写和记录方案；草稿仍仅组织者可读，用户身份由原可信登录决定，不接受客户端群资格声明。
- GO 创建入口保留直接创建，新增朋友筹备；团建与朋友筹备均有本人管理/填写记录入口。组织者记录方案后，可带入独立创建草稿，补齐安排并走原预览确认。成员、同意、费用和预约不复制；本片不自动把筹备答卷变成报名，不建立正式活动与旧筹备的自动回写关联。
- roster 在 RepeatableRead 内判断当前管理者或有效 joined 席位；其他人只查询/返回人数，连 SQL select 也不取报名名。保位待接受仍属于 joined，待审批或已退出不获名单权限。
