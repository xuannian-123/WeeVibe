# 整场取消：开始前最小闭环

依据原 Issue #5 的“延期取消”范围，以及[首版规则](../11-首版成局加入与补位规则.md)中当前管理者负责取消、保留历史、不自动退订退款或还原管理归属的明确约定。

## 本片能做什么

当前管理者可在所有环节均尚未开始时，显式确认取消**整场活动**。必须有有效主环节及至少一个未取消环节，所有历史段的起止/截止时间可核对；无效或缺失安排关闭操作。报名截止已过但尚未开始，不因此禁止本片取消。

部分环节已开始、全部结束等后期首次取消**本片尚未启用，规则待确认**。这不是宣称用户禁止后期取消，也不把某段开始当成其他所有业务的全局禁止。已成功的原取消键在后期仍可只读恢复当前结果。

本片没有恢复/撤销取消入口。取消后保留活动链接、管理者、原安排、全部申请/参加/答卷记录、历史接受、费用、核实/预订及原成局确认数据，不删除、不自动退出成员，不将pending改成伪拒绝，不把问卷自动定案或生成新的通知。正式当前状态因活动已取消，不再显示可加入或已成局。

**没有退款、扣费、自动退订、取消商家订单或代发外部消息。** 原预约和费用由相关人员另行处理。

## API 与事务

`POST /api/v1/activities/:activityId/cancel` 严格只接收 `expected_revision`、`idempotency_key`。身份来自服务端 session；当前管理者检查在成功旧键读取之前，不让旧管理者通过幂等重放恢复权限。

服务沿用父活动锁和原 Serializable 整笔重试。新命令核对当前版本，等待锁和异步读取之后再采样时间；只修改 `Activity.cancelledAt`、`Activity.revision`、取消事件和成功幂等键。任意写入或最终快照失败整笔回滚。相同成功原键不改取消时间、不重复事件；不同语义复用键冲突，已取消后新键不再新取消一次。

取消与审批/参加/需求共用原父活动锁。取消先成功后，新审批/参加/答卷等拒绝；若审批先成功，取消旧版本需要刷新后重新确认，已提交的席位保持历史。需求答卷先成功不被取消删除；取消先成功不允许后续新答卷。这些不表示网络中已发请求可以被撤销。

## 相邻入口取消保护

| 入口 | 取消后的新行为 | 已有历史 / 已处理原键 |
|---|---|---|
| 申请、审批、分段退出/晚到、主段核实/成局 | 原服务拒绝新写，不以旧按钮继续操作 | 原服务已有成功键仅返当前取消快照，不新占位或复活成局 |
| 本人pending撤回 | v17范围外明确未启用，不暗中当退出 | 成功撤回原键可只读恢复，不复活申请 |
| 需求创建/保存/发布/填写/提前截止/定案 | 服务端均拒绝关联活动取消后的命令 | 既有答案和公开/本人/管理者历史按原权限读取；不会伪造截止/定案事件 |
| 需求详情能力 | `can_edit/can_close`补上取消条件；其他写能力已有取消保护 | 取消提示与服务端一致，不再出现明明不可写却标可操作 |
| 本人安排审阅/重接受 | 新接受拒绝，绝不把取消当同意新版 | 本人已有占位历史仍可查；已有成功接受键只读返回当前状态 |
| 邀请创建 | 禁止新建取消活动的邀请来源 | 公共旧来源返回`cancelled:true`；主动保存历史来源仍可用，明确已取消且不授席位或群权限 |
| C1协调准备/候选边界 | 来源读取即拒绝取消，等待provider后的来源复核也拒绝 | 不生成/应用取消活动的建议，无真实模型调用 |
| 账户/个人收藏/已读/头像 | 维持本人独立权限，不因一场取消禁用全部账户 | 活动/邀请历史照常可见为取消状态；不新增假退款或推送 |

没有交接写系统，不能将现有取消字段视为已经完成未来WG-06“待交接失效”全闭环。

## 前端与恢复

仅当前管理者显示入口，确认文字准确区分整场取消与退出。确认前同步锁、同屏写互斥；来源actor/session、活动快照和页面epoch贯穿确认、`/me`、最终同步transport preflight及结果确认。hide/unload/unmount后不新发，已发晚响应不修改另一页/账号。

原请求在发送前按活动和actor保存。未知结果保原body/key，同身份重新读取后手工恢复；不自动发、不向B账号重放A的请求。成功仅认可匹配活动/当前管理身份/取消状态/版本的有效响应。服务端冲突需重新核对，不将本地按钮状态当取消成功。

## 真实验证层级与回退

专项调用实际取消服务、原相邻服务/DTO/route及实际客户端/组件；数据库和原生传输为离线替身。事务回滚、锁后时钟和两种顺序用例不是实际PostgreSQL并发证明。最终全量/类型/小程序/API/WASM结果另见交付日志。

无新表/迁移、无部署、无真实PG/原生/模型调用；第9条CAS迁移实库和既有PG业务执行限制保持。v17独立源码/dist可回退，但源码回退不等于数据库回滚，也不能把已发生的取消或在途请求撤销。
