## 保留的五题

活动昵称是独立前置步骤，不计入五题：

1. 哪天、什么时间有空？
2. 你准备从哪出发？仅本人。
3. 这次你的预算是多少？仅本人。
4. 这次想吃、喝、玩些什么？
5. 你想要什么，又想避开什么？

关键词沿用现有 `gatheringSections` 与业务契约，没有另造一套选项。原有填表、已定案只读、本人确定项选择和最终保存能力保留。

## 实际行为

- 使用 C 字体、奶白底、荧光绿操作、淡紫私人回答、紧凑消息与留白；未使用局长的前端组件。
- 已有实质答案跳过，默认活动日期不等于用户已回答；空白私人项不自动标记配合。切换填表修改后，对应题重新核对。
- 可以选择结构化控件，也可以输入回答。日期、金额、关键词先经本地受控规则解析；含糊内容保留原文并追问，不静默代填。不会将规则解析冒充每轮模型调用。
- 金额0保持0；明确“愿意配合”会清掉本题原私人限制，不表示免费、报名或同意最终安排。私人出发地继续保留既有地图选点、定位、地址搜索与权限能力。
- 本轮公开原话按题归属；重答或清空只替换本题，避免旧句和新句矛盾同时送去整理。历史原始备注与其他题回答保留。手动修改公开备注视为本人重新整理备注。
- 顶部返回先回昵称步骤，保留当前草稿、其他题和未发送内容；再进入时定位缺失题。明确取消沿用既有放弃本次编辑的行为，不会保存。
- 进入或修改题目滚到题头，避免直接落到长选项列表末尾；正文只有一个滚动区，关闭／返回和底部操作持续可见。
- 五题完成／明确留待定后才整理；整理由现有 `organizeGathering` API 执行，昵称、预算、出发地不进入模型。失败保留全部回答，可重试，或明确选择“尚未经 AI 总结”的手工核对。
- 整理结果用新 C 展示，公开与私人分组；确定项必须本人点选，允许一个都不选，最后才调用父层保存。整理本身不自动报名、发布、占席或确认最终安排。
- 新参与者原有提交后参与提示进入确认页；保存待核对的真实提示与原请求重试也进入固定界面。待核对期间不解锁重新编辑或再次提交，重试保持原请求及幂等键，避免新页面遮住父层恢复入口。
- 忙态、外部保存／只读、切账号、隐藏与卸载沿用来源票据；迟到结果不显示旧私人信息，不解除业务锁后自动写入。

## 后端与共享规则

当前部署的真实接口是公开偏好整理，并非多轮会话服务。本轮复用该接口，不新增会话表、请求协议、数据库迁移或模型供应商。前端问答推进使用本地受控逻辑，完成后才请求真实公开整理。

核对发现原共享公开文本守卫能拦数字金额与“预算”，但漏“人均两百”“花费两百块钱”等中文表达。已在 `packages/contracts/src/gathering-rules.ts` 修复已有守卫，并让本地对话解析复用；普通地点、免费活动、家庭友好、耗时与数量表达保持允许。合法私密金额和地址仍可填写本人栏位。

共享代码修改不等于远端 API 已更新：新小程序构建使用本轮规则，已部署旧 API 的同一修复仍需后续经授权发布。没有在本轮自行部署。
