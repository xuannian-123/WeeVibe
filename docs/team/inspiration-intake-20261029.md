# 灵感地点进入筹备填写

本批依据用户最新要求开发，基线为 `55d7f15`。本批不是朋友出游/团建整体流程改造完成回执。

## 页面与数据对应

- 灵感一级分类采用“干什么”中的吃、喝、玩，二级直接复用相同按钮词表，不再另造一套分类名。搜索与地点归类使用共享规则；不能识别的地点保留为地点想法，不擅自选成某项活动。
- “约大家去”将选中的地点以本人隔离的来源指针交给 `gathering?new=friend&inspiration=…`，直接展示活动昵称页。地点来源无效或属于其他账号时拒绝使用。
- 来源草稿使用独立后缀，保留原有普通筹备草稿和未知结果请求。新增资料不等于创建活动或报名。
- 例如肯悦咖啡（林泉店）：勾选喝中的咖啡，文本框填写“咖啡：肯悦咖啡（林泉店）”。共享契约的可选 `keyword_notes` 保存文字，`selected_places` 保存分类、按钮及地点来源资料。旧数据不含新字段时仍可解析，无数据库结构迁移。
- 前后端依据同一条目生成 `drink_0`，展示为喝／咖啡：肯悦咖啡（林泉店），AI整理结果默认确定。默认确定由已选资料推导，不由模型决定。本人可取消确定；修改地点文字或取消咖啡选择后，不再自动认定原地点确定。
- 私人出发地保留地图选择、手动描述及清除定位，移除独立获取定位和搜索地址入口；不向共享内容或模型发送私人出发地。

## 验证

- 全量214文件、4067项回归通过；随后新增的归属隔离和未知分类用例随相关组件与规则共60项通过。移除了旧获取定位入口对应的10个过时用例，保留地图生命周期/取消/只读等测试。
- 全工程类型检查通过；演示配置小程序和API standalone构建通过。
- 新建独立loopback PostgreSQL并应用17条迁移，原有8组业务/隐私/HTTP/通知验收及新增灵感地点创建、幂等、保存回读脚本均通过。没有写共享数据库；供应商调用为明确测试替身。
- 新验收脚本 `scripts/check-inspiration-intake.ts` 已加入CI，验证真实数据库中的分类、文字、确定状态及地点来源资料，不仅验证本地展示。
