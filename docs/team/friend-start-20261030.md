# 朋友出游首屏核对 · 2026-10-30

> 历史记录，首屏三卡与朋友独立安排／明细编辑已被用户后续决定取代。当前以[单一整理入口与依赖清理](friend-intake-20261030.md)为准；原生成／检查脚本已转发新版预览，旧截图和下方数字仅是当时验证，不能当作当前设计或新版验证。

本轮用户明确指定：进入朋友出游先显示 AI 整理、活动安排、其他明细三张卡片，不增加直接创建／先筹备分流。用户随后明确纠正：Logo、返回按钮也必须使用现有 C 设计，不能保留首版视觉。

## 本地实现

- 首页与灵感带入进入朋友总览，移除自动进入填写的 `startWithIntake` 开关。
- 首屏使用独立 `GatheringFriendStart`，复用首页 `CWordmark`、现有 `CIcon` 和 `CAction`；单行头部包含图标返回及小写黑绿字标。去掉首版文字 Logo、口号、文字箭头返回与重复返回区。新朋友入口身份加载期间也不渲染旧头部。
- AI 整理标必填，完成后显示活动昵称及日期。保存安排、明细后刷新摘要；取消修改保留原草稿；账号草稿隔离保持。
- 总览移除发起按钮。新建朋友局的表单仅在偏好最后一页提供整理入口；确认确定项后进入独立 C 风格最终预览页，唯一新建动作在此执行。已整理草稿可以从 AI 卡片继续最终预览，不需要重复整理。安排及明细可在最终预览中返回修改。
- 共用填写控制器增加仅新建局头生效的 `creating` 模式；小橘头问题顺序、回答解析、模型接口及聊天展示保持。填写昵称和日期后才可完成创建流程，参与者原有保存流程保持。
- 最终创建沿用 `POST /api/v1/gatherings`、共享 `gatheringCreateSchema`、身份检查和幂等重试；不增加中途创建接口。偏好、安排、人数费用一次提交。未明确勾选确定的日期不再写入 `confirmed_details`。网络结果未知时恢复原请求到最终预览，不自动重发；总览仅提供查看恢复入口。

## 连续页面复核（用户要求清除整段首版痕迹）

- 昵称加统一 C 字标与图标返回；基本偏好／吃喝玩／想要／想避开使用独立 `GatheringPreferenceForm`，不再渲染旧文字返回、旧模式条、旧面板和旧底部操作布局。低层输入组件继续复用，不另造数据状态。
- 整理确认使用同一确定项控制器，填表以 C 流程页呈现，小橘头继续原对话布局。两个方式均保留明确确认、返回修改和保存失败恢复；仅允许日期及吃喝玩成为确定项。
- 朋友安排、明细编辑使用 `GatheringFriendDetails`；发起成功使用 `GatheringFriendCreated`，仅在现有创建请求得到匹配身份的响应后展示。原通知授权逻辑保留，成功页使用 C 样式入口。
- 预算格式与范围在基本偏好页校验；公开补充中的私密信息在离开当前页前检查，不发送给 AI。连续点击下一步不会跨页。
- 清空只清当前页字段、对应确定项和关联地点；基本偏好／想要页的可见补充可清空，想避开页不清其他页补充。不再连带丢弃未改动的日期／吃喝玩确定状态。
- 新流程页每次切步恢复到页首。表单／昵称底部操作扣除系统已缩小的窗口高度，避免键盘导致重复上移；小橘头的问答顺序、解析、模型接口保持。
- 预览增加 11 个逐屏截图入口，包括昵称、四页偏好、确定项、最终预览及发起按钮、安排、明细和成功。成功页为明确离线响应示例，不是共享环境创建结果。
