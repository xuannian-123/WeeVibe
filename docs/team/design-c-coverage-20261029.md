## 返回、弹层与滚动的横向差异

1. **主导航与二级页面**：公开基准只在主页面和收藏页显示底部导航；当前首页控制器无条件渲染 `CNavigation`，设置、关于、隐私、帮助、邀请、编号和活动列表也保留导航。不是后端字段导致的视觉差异，应统一页面层级后再实现显示条件。
2. **列表状态**：`useTabScroll` 已为四主导航记录位置，灵感／收藏和我的／收藏也有来源缓存；不要删掉这些已有能力。活动列表仍没有按“我组织／我参与”分别记住筛选和滚动；当前 `subpage` 字符串切换不等于公开站的路由栈，进入更多子页会导致列表重建。
3. **系统返回**：公开站使用浏览器 history 管理页面与弹层；当前多个二级界面仍在同一个小程序页面内用 state 切换。按钮能返回并不证明 Android 系统返回／微信原生返回会先关闭当前弹层或返回上一子页，需明确桥接或真实页面栈方案，不能复用浏览器结论。
4. **弹层关闭**：C 弹层关闭按钮和遮罩关闭已有；头、底操作固定与单一正文滚动已有。基准拖拽条支持下拉关闭；当前 `c-sheet-grip` 仅是视觉条，无对应拖拽事件。是否保留拖拽需核对，不可把视觉条视为已实现手势。
5. **层叠返回**：基准“范围→城市→关闭城市”返回原范围；当前先关闭范围再开城市。需明确保持原范围草稿还是关闭回列表，同时保留当前“未应用不改变范围”的规则。
6. **组件预览的证据范围**：既有120组检查是实际展示组件在浏览器适配器中30种 fixture × 四宽度的检查；相关9项交互是离线预览状态机检查，不等同于生产控制器、微信页面栈和权限的端到端验收。真实控制器已有的测试可支持对应细项，但本审计没有重跑测试或调用共享业务服务。

## 建议下一批交付

**下一批先完成6页＋3个表面**，沿用当前 C 字体、分隔、图标、按钮和留白：设置／隐私／帮助／关于4页，已保存邀请／编号2页，更多菜单／退出确认／登录3个表面。预览应能连点走完“我的→设置→任一说明→返回设置→返回我的”和“我的活动→更多→邀请或编号→返回原活动列表”，包含各自空态、错误、取消、未登录态。

同时补齐两项会直接影响核对的基础交互：活动列表两组独立筛选和滚动记忆；二级页底部导航／按钮返回／系统返回的统一规则。它们不新增业务功能或后端接口，但决定重做页面是否真正可用。

**再做既有页面细节批次**：城市最近选择与键盘、范围叠层返回、灵感错误重试、消息错误与空态、收藏空态及GO详情撤销、头像昵称保存一致性。先用静态／离线可交互核对具体差异，用户确认后再作为新包手机验证的范围。不得据本清单擅自删除已有入口或改动私密字段规则。
