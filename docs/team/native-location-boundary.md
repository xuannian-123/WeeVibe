# 主动定位与页面来源保护

## 修复范围

原灵感“查看附近”和首页“获取当前位置”在等待微信定位时，账号切换、页面隐藏或卸载后仍可能把旧操作坐标用新会话发送。修复只在这两个入口及相邻地点交互内：

- 主动点击后捕获原会话和页面代次；固定会话 `/me` 验证真实身份后才调用原生定位。身份响应无效或未配置时不索取坐标。
- 定位返回后、地点请求的最后同步 transport 前、响应采用前均复验来源；Authorization 固定原会话，不读取新账号 token 替代。没有新增自动定位、定位权限或 provider。
- hide、unload、unmount 使当前代次失效；重新显示不复活旧操作。首页关闭/重开城市弹层、手输或选择城市，灵感修改关键词/城市等会使旧结果失效，不能覆写新选择。
- 同步锁防重复点击。正常城市识别只填建议，仍需本人确认后才保存城市名称；不保存原始坐标。未登录沿用原行为：手选城市可用，自动地点服务需登录，不新增游客限制。
- 灵感普通搜索沿用同模块固定会话客户端；收藏仍用原账户服务。地图导航仅用户点击原 `openLocation`，取消或失败给通用可恢复提示，保留地点/地址；不显示 native 原始错误，也不将按钮点击声称导航成功。

已发出的请求无法保证撤销。生命周期保护防止尚未发送的旧操作发出，并忽略已发请求的过时结果；不能宣称服务器未收到、删除了已经收到的位置或系统导航已取消。地图服务既有服务端隐私/日志策略未在此片重写。

## 证据与边界

修复前实际 React 组件＋原客户端、合成 native/transport 复现了跨账号和离页后发送；地图拒绝缺反馈另有复现。修复后组件/客户端检查正常路径、固定 bearer、身份/定位/请求三等待阶段、多个生命周期回调、手动输入抢占、重复点击与取消重试、未知响应及相邻收藏。最终数量与独立审计见交付日志。

本轮没有真实定位、地图供应商、微信原生、真实 DB 或新 HTTP 监听验收；没改后端、共享 transport、契约、迁移、依赖或模型调用。城市文案仅准确说明已实现的“地点浏览及新建时搜索城市默认”，不覆盖旧编辑或已选地点。

## 获准真机后的最短验收

两入口分别执行：主动点击→拒绝权限/取消→手输仍保留；正常返回→首页手工确认才保存。等待期间切账号、隐藏再显示、关闭弹层、改变搜索词，不应新发旧坐标或覆盖新内容；已发晚返回不提示旧结果成功。地图打开失败应有安全提示，成功不追加服务查询。使用获准测试身份和匹配后端，不能因离线测试通过省略原生验收。

回退源码与构建不会撤销请求或数据库记录，也不是数据库回滚。继续沿用 [晨间验收](morning-acceptance.md) 与 [安全矩阵](write-boundary-matrix.md)。
