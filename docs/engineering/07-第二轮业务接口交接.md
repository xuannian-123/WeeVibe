## 1. 稳定共享契约（本轮唯一字段依据）

源文件：[activities.ts](../../packages/contracts/src/activities.ts)，由index导出。TypeScript类型为CreateActivityInput、ApplyToActivityInput、DecideApplicationInput、ActivityDetail。四个客户端方法固定为createActivity(input)、getActivity(id)、applyToActivity(id,input)、decideApplication(id,applicationId,input)。本轮所有方法返回最新授权ActivityDetail，不返回另一套局部响应。

| 方法/路径（均在/api/v1） | 请求字段 |
|---|---|
| POST /activities | idempotency_key、name、timezone、main_segment_ref、segments[]、participating_segment_refs[]、可选display_name |
| GET /activities/{activity_id} | 路径为UUID；允许不带会话查看可邀请的最小安排，不返回他人申请或身份信息；会话存在则校验 |
| POST /activities/{activity_id}/applications | idempotency_key、expected_revision、segments:[{segment_id,plan_revision}]、可选display_name |
| POST /activities/{activity_id}/applications/{application_id}/decision | idempotency_key、expected_revision、decision:approve或reject |

创建段字段：client_ref（客户端稳定键，不能用数组下标/类型当身份）、type（sport/dinner/karaoke/drinks/board_game/custom）、name、starts_at/ends_at/deadline_at（带偏移ISO时间）、minimum_participants、capacity、location、fee、requirements。主段引用与本人所选client_ref必须存在且不重复；本人可明确选择空集合，不因管理自动占位。数组顺序即行程顺序，开始时间须非递减；未批准时间重叠一概规则，不把排序检查冒充转场可行。

location={name,address:string|null,source_url:http(s)URL|null}；手填不等于核实。fee={kind:unknown/per_person/total/per_hour,amount_cents:整数分|null,currency:CNY,note:string}，unknown必须null，已知金额须明确；0是明确免费而不是未知。requirements可空字符串。金额/人数以PostgreSQL Int可承载范围校验，文本上限以Zod源码为准。工程交付后主对话将活动请求统一扩为64KiB有界流读取，小程序同步预检；认证/地图保持默认4KiB。

## 2. 响应、页面与隐私

ActivityDetail包含activity_id/name/timezone/revision/server_time/main_segment_id/cancelled_at/formation_status，以及segments[]。

段含segment_id、client_ref、position、plan_revision、完整安排、cancelled_at、has_started/is_join_open、核实/预订状态与counts。counts分别给occupied_count、accepted_count、pending_acceptance_count、remaining_capacity、meets_minimum/is_full；待重接受仍占位，申请不占位。

viewer={user_id:null或本人UUID,is_manager,participations,applications}。participations只包含本人记录（joined/awaiting_acceptance/exited），viewer.applications只本人申请；根applications仅当前管理者返回，其他人字段省略。管理者申请对象含application_id、applicant_user_id、display_name:null或本人提供昵称、状态、段ID及接受版本、时间。普通详情不返回他人昵称、OpenID、会话、数据库错误或申请列表。

本轮可直接用activity_id定位邀请目标，这是明确的普通可访问活动定位，不声称不透明邀请码、来源归因、完整分享卡或成员名单页面已完成。知道activity_id不能获得写权限；所有写由真实会话user_id决定，管理审批再核数据库当前管理归属。

创建/审批不自动成局；本轮formation_status为not_confirmed。达到最低与满员分开显示，核实/预订初始unknown。WG-04成局、退出和WG-05+编辑/交接不抢做，但模型保留占位状态和接受版本，允许后续实质变更保位再接受。

## 3. 幂等、冲突与整体事务

idempotency_key是8—128位字母/数字/冒号/下划线/短横线；每次新意图生成新键，网络重试沿用原键和原请求。服务端按同一操作者＋键查记录，校验操作/活动/申请作用域及规范化请求摘要；不同用户不能读或重放他人的结果，同一用户同键不同语义409 IDEMPOTENCY_CONFLICT。

重放不再执行写入，并返回当前权限下最新快照，而非旧申请状态或旧管理权限列表。审批重放也要先核当前管理者。版本校验在合法幂等重放之后，故已成功请求不会因自己的revision递增而重复失败；新请求必须带最新expected_revision，段接受版本也逐项检查。

申请只包含本次新增段；已参加段不混入，无部分新申请。多个目标段任何一个已截止/开始/取消、无位、接受过期、已有本人占位或待处理申请，整次失败，不少批、不改变原参加。批准/拒绝和所有写入为数据库事务，批准才整体写全部席位和有效接受。截止/容量/版本/权限均在事务内重取；并发最后席位不能靠前端计数保障。

错误结构沿用{error:{code,message},request_id}，通用中文、no-store。常见400 INVALID_INPUT，401 UNAUTHENTICATED，403 FORBIDDEN，404 NOT_FOUND，409 VERSION_CONFLICT/ARRANGEMENT_STALE/CAPACITY_FULL/SEGMENT_APPLICATION_CLOSED/ACTIVITY_CANCELLED/ALREADY_JOINED/APPLICATION_ALREADY_PENDING/APPLICATION_ALREADY_DECIDED/IDEMPOTENCY_CONFLICT/CONCURRENT_MODIFICATION。重新取详情再操作，不能超时就假定已批准。

### 事务与模型的实现要点

创建、申请、批准/拒绝全部通过现有withDb进入PostgreSQL事务，无内存生产后端。所有修改事务采用Serializable；已有活动写入先用参数化SELECT Activity FOR UPDATE锁同一活动，再查当前管理者/版本/所选段名额和截止。审批和新增段占位是在同一个事务里处理完整目标集合，任何一步失败回滚整个申请状态、全部席位、事件和幂等记录，不逐段提交。

P2034、唯一键竞争P2002及raw SQL序列化/死锁40001/40P01支持最多三次完整事务重试；耗尽返回409 CONCURRENT_MODIFICATION，不继续失败的半个事务。此为源码行为及设计审查，真实数据库是否按预期重试/回滚尚未实测。

幂等记录只有成功事务提交时写入，主键为actorUserId＋key；摘要包含actor、操作/目标作用域和经Zod解析的语义（申请选段顺序不影响摘要、创建行程序列保留，明确时刻规范为UTC）。不同actor不能读取其他人的记录，不同payload/操作/活动/申请不能借旧成功key重放。重放返回当前授权快照而非过去的申请状态或管理权限；角色已变化的旧管理者即便持原成功key也不能审批。失败事务不留成功记录，修改意图应生成新key。

Participation一人同段唯一，joined始终计占位，acceptedPlanRevision不等于该段当前planRevision时仍占位并显示awaiting_acceptance；exited不计占位。批准复制申请时本人明确接受的版本，不用批准替代本人接受新版。既有段不混进新增申请，失败不改既有记录；未来重新加入可复用exited记录，但本轮不实现退出接口。

主段用单引用而非多个布尔值，复合外键保证属于同一活动。创建事务先生成Activity/各段，再设置mainSegmentId；数据库字段为可空以支持该事务内过渡，API提交前确保恰有一个合法主段，不会暴露半创建。当前无form/核实接口，正常新建均not_confirmed/unknown。未来成局引用字段已留，未假造预约。

拒绝整份pending申请不占位，因此只核当前管理权、活动未取消、全局版本及pending状态，可在该段过截止或安排改变后拒绝清理，不强迫其具备批准资格；批准才对全部目标重查截止/开始、容量、本人已有占位及逐段接受版本。重复待处理申请如目标有重叠返回APPLICATION_ALREADY_PENDING；撤回/修改申请接口不在本批，需管理者拒绝后再新申请，后续由相应任务补齐。

GET详情采用RepeatableRead读快照；管理者身份从数据库currentManagerId计算。普通/匿名viewer没有根applications，已登录者只获本人申请和参加状态；非管理者不返回其他申请昵称/user_id，任何响应不返回OpenID或平台凭据。公开activity_id定位是本批有意采用的入口，不声称已完成不透明邀请码或邀请来源归因。
