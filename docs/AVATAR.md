# v6 分身谈判：设计与开发契约

> v5 让局长会做决定（DECISION.md）。v6 让每个人都有一个**替自己去谈判的 AI 分身**：分身了解你这次的需求、守住你的底线、在你授权的范围内替你让步；局长主持谈判、保证公平、守住所有人的秘密、最后拍板。
> 本文是四条开发线（A 活动与行程、B 分身与谈判、C 建档与授权书、D 谈判直播与体验）的共同契约。共享类型在 `src/lib/types.ts` 的「v6」一节，改类型先找 leader。

## 0. 一句话目标与验收

评委用手机入局：分身说出「我猜你这次……」，改一项、说一句「这周好累」，授权书生成；大屏直播 8 个分身谈判（门禁冲突、有人预算紧、有人想动有人想躺），能看到让步、交换、补偿一轮轮发生；局长拍板「下午攀岩 → 旁边吃安静的家常菜，9 点前结束，下雨换室内」；每个人手机上收到「你得到了什么、你的分身替你让了什么、为什么」；隐私自检同时跑，0 泄露。

硬指标（写成测试）：
- 新用户：建档 ≤ 5 屏、每屏可跳过；本次入局 = 1 句话 + ≤ 2 次点击 + 1 次确认授权书。老用户：1 次点击。
- 同样的输入一定得到同样的谈判过程和结论（确定性，沿用 v5 审计）。
- 隐私反事实检验覆盖谈判记录（§6），0 泄露。
- 底线每人最多 3 条（`MAX_FLOORS = 3`）。

## 1. 角色

| 角色 | 代表 | 职责 |
|---|---|---|
| 分身（每人一个） | 本人 | 守底线、争取想要的、在授权范围（give）内自动让步，超出范围私下问本人 |
| 局长（一个） | 整个群 | 主持、出方案、找代价最小的让步、做交换与补偿、按 v5 三级准则拍板、过隐私防火墙 |

不做"分身之间自由吵架"：嗓门大的人赢对老实人不公平。所有让步由局长按代价排序发起，分身只按授权书回应。

## 2. 授权书（Mandate）

授权书 = 本人交给分身的东西，三栏：

| 栏 | 含义 | 来源 | 分身怎么做 |
|---|---|---|---|
| 底线 floors | 绝不谈 | 本人确认过的硬约束：门禁（homeBy）、清真/素食、硬需求（need.kind = hard） | 死守，任何方案违反 = 这个人没被照顾到 |
| 可以让 give | 分身可自己做主的让步幅度 | 授权书滑块；默认值由风格决定 | 需要时自动让，不问本人，记进"分身替你做了什么" |
| 想要 wants | 尽量争取 | 软需求、预算、心情、想玩什么 | 进满意度；必要时可放弃（waiveSoft） |

规则：
- **底线 ≤ 3 条。** 超过时授权书要求本人选 3 条；没选就保留最早确认的 3 条，其余降为强度 3 的软需求（"想要"里最用力的）。理由写在授权书上："底线越少，分身越好谈；真正必须的事 3 条够用。"
- **give 默认值按风格**（`AvatarStyle`）：
  - easy 随和：lateMin 30 / stayCutMin 30 / budgetUp 30 / commuteUp 20
  - balanced 平衡（默认）：15 / 15 / 15 / 10
  - firm 坚持：0 / 0 / 0 / 0（并且 wants 的强度 +1，上限 3）
- 风格默认从这次说的话推断（"我都行" → easy；"这次就想吃火锅" → firm），本人可切换。
- 由 `MemberPrivate`（availability / budgetMax / dietTags / needs / mood）+ `mandate`（style / give / floors / status）共同决定；`mandateOf(member)` 是唯一的计算入口（B 实现，C 和 D 只读）。

## 3. 活动层：先定干什么，再定去哪（A）

### 3.1 发起方式
- 发起人说了品类（"周六吃火锅"）→ `spec.open = false`，同 v5，只是候选活动 = 这一个。
- 发起人没说或说"大家聚一下 / 你定"→ `spec.open = true`，`spec.category = "局长定"`，候选活动由局长从活动库里选。
- 发起人可给一个候选池（"吃饭或者桌游"）→ `spec.activities = ["hotpot", "boardgame"]`。

### 3.2 活动库 `ACTIVITY_LIB`（`planner/activities.ts`）
每种活动带属性（`ActivityDef`）：动静 energy 0–3、能不能聊天 talk 0–2、吵不吵 loud、有没有酒 alcohol、室内/户外 indoor、人均区间 cost、时长 minutes、适合人数 people、能否中途加入 lateJoin、是不是吃饭 food、高德搜索词 poiKeywords。首批 ≥ 24 种，覆盖吃（火锅、烧烤、家常菜、日料、西餐、自助、小吃）、喝（咖啡、清吧、奶茶）、玩（桌游、剧本杀、密室、KTV、电玩、台球、保龄球、射箭、攀岩、羽毛球）、看（展览、电影、Livehouse）、户外（徒步、公园野餐、骑行、露营）。

### 3.3 活动打分（不调地图，便宜）
每人对每种活动的契合度 = 心情（mood ↔ energy/talk）+ 想要/不想要（preferCategory / avoidCategory 及档案 activityTastes）+ 身体（body 限制 ↔ energy）+ 预算（cost 下限 ↔ budgetMax）+ 天气（户外 ↔ 预报）。
硬性的（"膝盖不好不能爬山"被确认为底线、清真、预算底线）直接排除。
按 v5 三级准则在**活动层**排出前 K 个"节目"（K ≤ 4），再对每个节目调地图搜店、走 v5 的 slot × poi 全量计算。地图调用次数不得超过 v5 的 2 倍。

### 3.4 节目 = 一段或两段
- 一段：同 v5。
- 两段：第一段"玩"+ 第二段"吃"（或反过来），第二段的店离第一段步行 ≤ 15 分钟。
  - 什么时候考虑两段：大家心情分化（有人想动有人想躺 / 有人想聊有人想嗨），或有人只能晚到而第二段 lateJoin。
  - 每人每段分别计算到场与满意度；只来得了第二段的人算"部分照顾"（cared 的定义扩展：两段里至少完整参加一段且硬约束满足且满意度 ≥ 保底线）。
  - `Proposal.segments` 有两段时，`proposal.slot / proposal.poi` = 第一段（老代码不改也能跑）。
- 晚到的人直接来第二段 = DECISION.md 的 R5（拆成两段），在这里落地。

## 4. 谈判协议（B）

五轮，全部确定性（同样输入 → 同样记录）：

0. **交底（密封）**：每个分身把授权书交给局长。公开记录只写"8 个分身交了授权书，其中 3 个有底线"（聚合）。
1. **局长出方案**：活动层 + v5 全量计算，找出推荐方案和卡点（`Diagnosis`）。
2. **让步**：对卡点找代价最小的让步（复用 `planRepairs`，代价含让步账）。
   - 在 give 范围内 → 分身**自动同意**，不打扰本人；写进本人的 `avatarLog`。
   - 超出 give、但不碰底线 → 私下问本人（v5 的 `NegotiationAsk`，口吻改成"你的分身来问你"）。
   - 碰底线 → 不问，换别的办法。
3. **交换与补偿**：
   - 交换：两人在不同维度各让一小步，两人都比各自坚持更好（例：A 晚到 15 分钟、B 多走 10 分钟，换来两人都能来）。局长在候选里搜"两人都让一步就都能被照顾到"的组合。
   - 补偿：让过步的人这次拿到补偿——两段式时第二段按他的口味加权挑；没有两段时记入让步账，下次局里优先照顾他（v5 已有，写清楚）。
4. **拍板 + 逐人解释**：按 v5 三级准则拍板；每人私下收到"你得到了什么 / 你的分身替你让了什么 / 为什么"。公开记录给出聚合结论。

谈不拢时的出路（按顺序）：拆两段 → 加候选时间（建议发起人，一键）→ 接受有人来不了 + 记账补偿（R6）。分成两拨属于以后的路线，不做。

### 4.1 give 怎么进计算
- give 是"预先批准的让步"，**不是免费的**：用到 give 的候选给这个人记一笔小损失（让步代价），这样能不让就不让、要让就让得最少的人。
- 时间：`relax.maxLateMin = 45 + give.lateMin`、`relax.minStayMin = 60 − give.stayCutMin`（只在需要时启用，即该候选里不启用就会 absent / 未被照顾）。
- 预算：有效预算 = budgetMax + budgetUp，在 budgetUp 以内不算"超预算未照顾"，但计让步代价。
- 通勤：maxCommute 类软需求放宽 commuteUp。
- 底线永远不放宽。

### 4.2 只问会改变结果的问题（价值信息）
`worthAsking(juState)`：对某个人还缺 / 不确定的信息，只有当它的不同取值会改变推荐方案（或改变谁被照顾到）时才值得问。C 的授权书卡片据此决定要不要高亮某个空格；B 的谈判据此决定要不要追问。上限仍是 v5 的每人 2 问 / 每局 5 问。

### 4.3 谈判记录 `Negotiation`（公开）
存在 `Plan.negotiation`，大屏直播用。每条 `NegotiationEvent` 有轮次、说话人、类别、文字。
- 说话人只能是 `"局长"` 或**分身代号**（"分身 A""分身 B"…），代号按事件内容的规范顺序分配，**和成员身份、加入顺序、真名、分身名都无关**（§6）。
- 本人起的分身名（如"小橘"）只出现在本人视图（`avatarLog`、授权书、"你的小橘替你让了 15 分钟"），不出现在任何公开输出里。

### 4.4 本人视图 `avatarLog`
`MemberPrivate.avatarLog`：分身替你做的每件事（自动让步、守住了底线、争取到了什么、来问你的事、补偿）。结果公布后 30 分钟内可以**撤回**任何一次自动让步（`revoked`），撤回 = 这个人这一维的 give 视为 0，触发重算。

## 5. 收集：建档 + 本次需求 + 授权书（C）

### 5.1 首次建档"认识你的分身"（≤ 5 屏，每屏可跳过，约 1 分钟）
1. 给分身起名（默认"<你的名字>的分身"；名字里含真名时提醒"大屏不会显示分身名，但别人可能从名字认出你"——实际上公开输出也不会用它）。
2. 常从哪出发（可多个：家 / 公司 / 学校）+ 常用交通。
3. 底线（常见项一点即选：门禁几点、清真、素食、过敏、膝盖不好、不喝酒；最多 3 条）。
4. 平时花多少（50 / 100 / 200 / 不太在意）。
5. 滑卡 10 张活动卡（左滑不感兴趣 / 右滑喜欢 / 上滑超爱）→ `activityTastes`。
完成后分身说"好，我大概认识你了"，直接进本次授权书。

### 5.2 本次入局：边说边填
- 一进来就是授权书卡片，格子按档案预填（标"上次的"），空格就是方向：哪天有空 / 从哪出发 / 预算 / 这次的状态（想嗨 · 想安静聊聊 · 想动一动 · 想躺着）/ 想干什么（有想法就说，没有点「局长定」）/ 讲究（标签：怕吵、不能太晚、不吃辣、在减肥、不喝酒、清真、膝盖不好…）。
- 下面一个输入框（支持语音输入法），例句用这次局的真实日期和城市生成。
- 说一句话 → 抽取（v5 的 chatTurn + needs）→ 对应格子实时亮起；没亮的格子点一下补。
- 唯一的追问：推断出的硬约束要确认（v5 pendingConfirm），以及 §4.2 认为值得问的。
- 底部授权书三栏 + 风格切换 + "可以让多少"滑块 → 「就这样」完成。
- 老用户：直接看到预填好的授权书，"还和上次一样吗？"一键完成。

### 5.3 个人固定档案
- 「我说的」vs「分身猜的」分开存（`ProfileFact.source`）。猜的带把握度，**永远不能当底线**，只当默认值。
- 存：分身名、风格、常用出发地（多个）、交通、门禁、忌口、身体限制、平时预算、活动口味、局后反馈、让步账 / 公平账本（已有）。
- 「分身眼中的你」页面（`/me`）：每条可改、可删、可"忘掉"。
- 学到的偏好随时间淡化（半衰期 60 天）。
- 局后一键反馈（第二天）："昨晚怎么样？很棒 / 太累 / 太贵 / 太远 / 太吵" → 更新档案（太累 → 下次心情默认偏 chill、活动 energy 降权；太贵 → typicalBudget 下调…）。

## 6. 隐私（所有线都要守）
- 谈判记录、两段式方案、活动选择都是公开输出，必须只由公开因素 + 聚合数算出，过现有防火墙（`guardPublicText` 等）。
- 新增反事实检验 `negotiation`：把两个人的隐藏信息互换（`swapHidden`），公开谈判记录必须逐字相同。这就是为什么分身代号要按内容规范排序分配、而不是按成员分配。
- 心情（mood）、身体限制、活动偏好都是私密的，公开里只出现聚合（"有 2 位朋友想安静点"，人数 ≥ 2 才说具体类别，1 人时只说"有人"）。
- 分身名只在本人视图。
